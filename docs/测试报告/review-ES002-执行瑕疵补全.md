### 经验 2：PowerShell 5.1 中文路径 + 纯 ASCII 脚本的代码点拼装范式

**问题模式**：Windows PS 5.1 默认 ANSI 读无 BOM 的 .ps1，含中文字面量会乱码；cmd 层 `-File '中文路径'` 参数会因引号处理破坏路径。

**可复用解法**：
1. 脚本主体用 `[char]0xXXXX` 代码点拼装中文字符串（运行时是 UTF-16，正确还原）。
2. 跑脚本时不在 cmd 用 `-File '中文路径'`，而是在 PS 内部用 `& $codepointBuiltPath -Root <root>` 调用。
3. 路径核对用 `$p='...\'+[char]0x67B6+[char]0x6784+...; Test-Path $p`。

**本次实践**：本评审所有 Test-Path 自检均用代码点拼装，G7 重跑用 PS 内部 `&` 调用，全部成功。

### 经验 3：反幻觉审查的"独立重跑"原则

**问题模式**：上游角色（如 team-standards）的报告可能含幻觉（虚报字节数、虚构行号、夸大命中精度），Reviewer 若抄报告文字做评审，会被幻觉带偏。

**可复用解法**：
1. **字节数独立核对**：自己跑 `Get-Item <path>.Length`，与报告对比。
2. **行号引用独立核对**：自己 Read 上游文档对应行，确认引用内容真实。
3. **门禁命中精度独立核对**：自己重跑门禁脚本，对比输出与报告声称。
4. **历史事实独立核对**：自己 `git show <commit>~1:<file>` 对比改动方向声明。

**本次实践**：5 条 Standards 声明全部独立重跑复现，包括用 `git show 2f84e10~1:pom.xml` 独立验证"HEAD 本无 executions"这一历史事实。
