## 二、本机单元/回归测试

### 2.1 首轮基线：4 个存量测试报错 → 连环挖出两个被掩盖的缺陷

**现象**：首轮 `mvn test -pl eaiselp-runtime -am`，runtime 模块 4 Errors——`DerivationEngineTest`（3）+ `DerivationEnginePersistenceFailureTest`（1），均为 @SpringBootTest 上下文加载失败。

**缺陷①（存量测试基建，测试配置修复）**：test profile（`application-test.yml`）用 H2（`MODE=MySQL`）+ `schema-h2.sql` 初始化，但主 `application.yml` 的 Flyway（`enabled: true`）未在 test profile 关闭——Flyway 在 H2 上执行 MySQL 专有语法的 `V1__baseline.sql`（`CREATE DATABASE`/反引号）必然失败。该缺口自 cb4addf（flyway-mysql 引入）即存在，**非本 case 引入**；本 case 的 V4 迁移从未被执行到。
- **修复**：`eaiselp-runtime/src/test/resources/application-test.yml` 增加 `spring.flyway.enabled: false`（H2 建表继续走 schema-h2.sql）。

**缺陷②（P0 产品缺陷，本 case T04 引入，QA 修复 + 上报）**：修复①后上下文加载继续深入，暴露新错误 `NoUniqueBeanDefinitionException: QualityGateRuleService ... found 2: qualityGateRuleServiceImpl, qualityGateRuleService`。根因：`EaiselpRuntimeApplication` 的 `@MapperScan` 增加了整包扫描 `"com.eaiselp.runtime.hierarchy"`——该包内除 6 个 `*Mapper` 外还有 `StrategyService/ProgramService/ProjectService/PrincipleService/QualityGateRuleService/ProjectPrincipleService` 等 **Service 接口**，被一并注册为 MapperFactoryBean（bean 名与 @Service 实现类不同名），按类型注入即双 bean 冲突 → **Spring 上下文启动失败（生产启动同样失败）**。此前一直被缺陷①掩盖（上下文在 Flyway 阶段更早失败），单元测试与代码评审均未暴露。
- **修复（最小面）**：`@MapperScan(annotationClass = Mapper.class, basePackages = {...原四包...})`——只注册带 `@Mapper` 的接口。已逐一核验四包内全部 17 个 mapper（data 14 + adapter 1 + orchestration 1 + hierarchy 6）均带 `@Mapper`，对 mapper 注册零行为变化，仅剔除误注册的 Service 接口。
- **上报**：请 team-dev 复核该修复；该缺陷说明"本 case 交付后从未成功启动过 Spring 上下文"，建议部署机联测前先做一次真实启动冒烟。

## 本次经验沉淀

1. **接手测试先跑基线并做"失败归属"分层，能挖出被掩盖的产品缺陷**：本次 4 个存量测试报错，表面是测试配置问题（test profile 漏关 Flyway），修完后上下文继续加载才暴露真正的 P0——@MapperScan 整包扫描把 Service 接口注册成 mapper bean，Spring 上下文根本起不来（生产同样起不来）。教训：**"测试环境起不来"类失败要修到"上下文能完整启动"为止再下结论**，第一层障碍往往掩护着第二层；凡阻断启动的缺陷，单测（Mockito）与代码评审都天然探测不到，必须至少有一次真实上下文装配验证。

2. **评审报告的阻断项要在测试阶段逐项复核，不能照抄进已知限制**：本次复核发现 D2/D3 已被修复、D1 与现行 PRD 文本矛盾——若直接沿用评审结论，会把已修复项当缺陷阻断发布、又把编号锚点断言写错方向。教训：**已知限制清单必须带"复核时间戳+证据"，过期的缺陷描述比没有描述更危险**。

3. **不可见机制的单测要锚定 AC 的具体断言值，而不是泛化的非空判断**：新增 26 测全部锚定 PRD 数值/文案（33→66、8000 截断、`[P11|must]` 格式、must 拦截提示行、绑定全禁不回退租户全局），使评审报告的坐标级推演（门禁等价表、注入契约）转化为可持续回归的自动化护栏。
