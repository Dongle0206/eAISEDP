## 0. 设计原则

### 0.1 与 G1-G10 的关系

| 门禁组 | 管什么 | 配套标准 | 脚本 |
|---|---|---|---|
| G1-G6 | Maven 模块边界（ADR-001 P1-P5）| ES-001 | 质量门禁-模块边界.ps1 |
| G7-G10 | 产出物落盘 + Windows 工程 + Dev 报告 | ES-002 | 质量门禁-产出物落盘.ps1 |
| **G11-G15** | **平台承载规范（EA 蓝图 P6/P8/P10/P11/P13）** | **ES-003** | **质量门禁-平台承载规范.ps1** |

三组门禁互不耦合，可独立运行。任一阻断级 FAIL → PR 打回。

### 0.2 阶段性门禁的关键设计（G11/G12/G15）

P6/P8/P10 的技术债（角色硬编码 / 模型内联 / 过程资产未结构化）在 M2 SP-4/SP-6 完成前客观存在。若门禁一开始就 BLOCKER，会阻断 M1 现有代码的任何 PR。因此：

| 门禁 | SP-4/SP-6 完成前 | SP-4/SP-6 完成后 |
|---|---|---|
| G11（P6 零角色硬编码）| **WARN**（命中 guessType 违反点，提示 SP-4 待清除）| **BLOCKER**（命中 = PR 打回）|
| G12（P8 模型路由配置化）| **WARN**（命中 MODEL_MAPPING 违反点，提示 SP-6 待清除）| **BLOCKER** |
| G15（P10 过程资产结构化）| **WARN**（t_artifact 三字段全 NULL，提示 SP-4 待填充）| **BLOCKER** |

**阶段切换机制**：脚本通过 `-Phase` 参数控制（默认 `m1`）。SP-4/SP-6 完成后，team-standards 把默认值改为 `m2-sp4-done` / `m2-sp6-done`，相应门禁升级为 BLOCKER。切换记录到 ES-003 §11 变更日志。

### 0.3 排除规则（防误报）

| 门禁 | 排除项 |
|---|---|
| G11 | 单行注释（`//` 开头，去除前导空白后判断）；测试 fixture（`src/test/`）；配置文件（*.yml/*.yaml/*.properties）；体系 markdown（agents-config/）|
| G12 | 配置文件（*.yml/*.yaml/*.properties/*.sql）；测试 fixture（`src/test/`）|
| G13 | 代码注释中标注了 ADR 编号的（`@InterceptorIgnore` + 注释含 `ADR-xxx` 审批）|
| G14 | 现有 M1 Controller（无 v1 但属遗留，报 WARN 不阻断）|
| G15 | t_artifact 表不存在时（M1 无 DB 连接降级）|



### 2.3 退出码语义

| exit code | 含义 |
|---|---|
| 0 | 全部门禁 PASS 或仅 WARN（M1 阶段可合并）|
| 1 | 有 BLOCKER 级 FAIL（PR 打回）|

**注意**：WARN 不改变 exit code（仍为 0），但在控制台用黄色醒目输出，提示技术债待清除。
