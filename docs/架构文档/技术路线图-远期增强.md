## #10 全文搜索升级（LIKE → Elasticsearch）

### 现状
- `SearchController` → `ArtifactService.search()` 用 `LIKE '%kw%'` 全表扫描
- 产物 <1万条时无感知；>10万条时查询延迟 >2s

### 方案
```
当前: ArtifactService.search(kw) → MyBatis-Plus LIKE → MySQL
目标: ArtifactService.search(kw) → Elasticsearch → 多字段+分词+高亮
```

### 实施
1. Docker 部署 Elasticsearch 8 + Kibana
2. 新增 `EsArtifactAdapter` 实现 `ArtifactIndexSpi`
3. 派生产出落库时同步索引（Canal 或应用层双写）
4. `SearchController` 无感切换（Service 接口不变）

### 成本
- 开发：3-5 天
- 运维：ES 集群内存 ≥4G，监控 + 备份
- 风险：低（接口层不变，可灰度切换）

## #11 Redis 缓存

### 现状
- 限流用 Bucket4j 内存态（单机，多实例不一致）
- 模型路由 `ModelRoutingServiceImpl` 每次派生直查 DB
- 无分布式会话（JWT 无状态，但无法主动吊销 token）

### 方案
```
新增: Redis 6 容器
  ├── 限流: Bucket4j → Redis Bucket（多实例一致）
  ├── 缓存: t_model_routing 热数据 TTL 5min
  ├── 会话: JWT 黑名单（主动吊销）
  └── 分布式锁: 检查点审批防重复提交
```

### 实施
1. Docker 部署 Redis 6 + 密码认证
2. 引入 `spring-boot-starter-data-redis`
3. `ModelRoutingServiceImpl` 加 `@Cacheable`
4. 限流改为 `RedisRateLimiter`
5. 新增 `TokenBlacklistService`（logout 时写入黑名单）

### 成本
- 开发：2-3 天
- 运维：Redis 容器 + 持久化配置 + 监控
- 风险：中（缓存一致性、Redis 故障降级策略需设计）

## #12 企业适配器真实实现

### 现状
- 7 个适配器 SPI 中，Git/LLM/DocStore 有默认实现
- Ticket/CICD/IM/MCP 均为 Stub 占位（`log.warn` + 返回 null）

### 需求驱动
首个企业客户需要对接现有工具链时启动。

### 方案（按客户工具栈选择）
| 适配器 | 常见客户工具 | 实现 |
|--------|-------------|------|
| Ticket | Jira / 禅道 / 飞书项目 | REST API 对接 |
| CICD | Jenkins / GitLab CI / GitHub Actions | Webhook 触发 + 状态轮询 |
| IM | 钉钉 / 飞书 / 企业微信 | 机器人消息推送 |
| Git | GitLab / Gitea / Bitbucket | 替换 LocalGitAdapter |
| DocStore | Confluence / 飞书文档 | REST API 读写 |

### 实施
1. 按客户实际工具选 2-3 个优先实现
2. 每个适配器独立 SPI 实现 + 条件装配
3. 充分使用 MCP 协议减少定制开发

### 成本
- 每个适配器：2-5 天（取决于 API 复杂度）
- 风险：中（第三方 API 变更、鉴权方式差异）

## #13 K8s 容器编排

### 现状
- Docker Compose + Nginx 负载均衡（2 auth + 2 runtime）
- 手动扩容、无自动恢复、无滚动更新

### 方案
```
Docker Compose → K8s
  ├── Deployment（auth ×2, runtime ×2）自动健康检查 + 重启
  ├── HPA（CPU >70% 自动扩容）
  ├── StatefulSet（MySQL/Redis 有状态服务）
  ├── Ingress（替代 Nginx，自动 TLS）
  └── ConfigMap/Secret（配置 + 密钥管理）
```

### 触发条件
- 需要弹性伸缩（流量波动大）
- 需要零停机部署
- 多环境（dev/staging/prod）统一管理

### 成本
- 开发：5-7 天（Helm Chart + CI/CD 适配）
- 运维：K8s 集群（自建或云托管）+ 学习成本
- 风险：中（K8s 运维复杂度高，小团队可先用 Docker Swarm 过渡）

## #14 VS Code 插件

### 现状
- 用户通过浏览器 Web 界面操作 Case/派生/审计
- 开发者在 IDE 内无法直接触发派生或查看产物

### 方案
```
VS Code Extension
  ├── 侧边栏: Case 列表 + 状态 + 快捷派生
  ├── 编辑器: 内联查看 PRD/技术方案/代码产物
  ├── 命令面板: F1 → "eAISEDP: 发起派生"
  └── 状态栏: 当前 Case + 派生进度
```

### 触发条件
- 开发者反馈频繁在 IDE 和浏览器间切换
- 希望产物直接落地到工作区文件

### 成本
- 开发：7-10 天（TypeScript + VS Code Extension API）
- 风险：低（纯前端插件，不影响后端）

## #15 前端国际化（i18n）

### 现状
- `i18n.js` 框架已搭建，但内容仅中文
- 所有页面硬编码中文文案

### 方案
1. 抽取所有中文文案到 `assets/i18n/zh-CN.json`
2. 新增 `en-US.json` 英文翻译
3. 页面用 `i18n.t('key')` 替代硬编码

### 触发条件
- 海外客户需求
- 或产品定位需要英文界面

### 成本
- 开发：2-3 天（机械替换）
- 翻译：1 天（专业术语校对）
- 风险：低
