## 2. 规则详细定义

### 规则 G7 — 关键角色产出物必须存在物理文件（修复 IMP-004）

**断言**：以下 3 类产出物在 case 走完对应阶段后，**至少各存在 1 个**物理文件（且非空，Length > 100 字节）：

| 产出物类型 | 检查路径（相对项目根） | 触发条件 |
|---|---|---|
| Reviewer 评审报告 | `docs/测试报告/review-*.md` | case 走了 Reviewer 阶段 |
| QA 测试报告 | `docs/测试报告/qa-*.md` | case 走了 QA 阶段 |
| SE 技术方案 | `docs/设计规划文档/*-技术方案.md` | case 走了 SE 阶段 |

**通过判据**：
- 若 case 走了 Reviewer 阶段：`docs/测试报告/review-*.md` 至少 1 个，且 Length > 100 字节。
- 若 case 走了 QA 阶段：`docs/测试报告/qa-*.md` 至少 1 个，且 Length > 100 字节。
- 若 case 走了 SE 阶段：`docs/设计规划文档/*-技术方案.md` 至少 1 个，且 Length > 100 字节。

**M1 阶段简化**：脚本默认要求 3 类都至少 1 个（覆盖最常见全流程 case）。若 case 跳过某阶段（如纯文档 case 无 SE），Reviewer 验收时手动放行并在 PR 描述注明"本 case 跳过 SE 阶段"。

**类别**：阻断。

**违反时的处理**：
- 找出缺失的角色，要求其补 Write 落盘。
- 若 Agent 已输出在回复里但未落盘：把回复内容 Write 到指定路径即可，无需重做评审。

### 规则 G8 — 禁止 `$null` 字面文件污染（修复 IMP-006）

**断言**：工作区（项目根递归）**不得**存在名为 `$null` 的文件。

**检查方法**：`Get-ChildItem -Recurse -Force | Where-Object { $_.Name -eq '$null' }`

**通过判据**：上述查询返回空。

**类别**：阻断。

**违反时的处理**：
- 删除字面 `$null` 文件：`Remove-Item -Path '<full-path-to-$null>' -Force`
- 排查源头：通常来自 `> $null`（有空格）或 cmd 上下文误用，按 ES-002 §3.2 修正脚本。

### 规则 G9 — git commit message 中文显示正常（修复 IMP-006）

**断言**：最近 N 条（默认 5）commit message 的中文显示正常（非乱码 / 非八进制转义）。

**检查方法**（M1 阶段简化版）：
```powershell
# 取最近 5 条 commit subject
$subjects = git -C $Root log -5 --format='%s'
# 检查是否含乱码特征（连续 ? 或 \xxx 八进制转义）
foreach ($s in $subjects) {
    if ($s -match '\?\?\?' -or $s -match '\\[0-9]{3}') {
        Write-Host "[WARN] 可能乱码: $s"
    }
}
```

**通过判据**：最近 5 条 commit subject 无乱码特征。

**类别**：警告（M1 阶段；M2 接 CI 后升级为阻断，加严格 UTF-8 校验）。

**违反时的处理**：
- 不阻断 PR，但在 case 归档时提示 Ops 用 `git commit --amend -F <utf8-file>` 修正最后一条 commit。
- 后续 commit 一律用 `-F <utf8-no-bom-file>`（ES-002 §3.1）。

### 规则 G10 — Dev 报告改动描述以"对照 HEAD"开头（修复 IMP-007）

**断言**：Dev 报告文件（`docs/过程跟踪文档/case-*/dev-report-*.md`）若含改动方向描述（新增 / 删除 / 修改），**至少 1 处**以"对照 HEAD"开头。

**检查方法**（弱语义检查，仅文本前缀匹配）：
```powershell
# 找所有 dev-report 文件
$reports = Get-ChildItem -Path "$Root\docs\过程跟踪文档\case-*" -Recurse -Filter 'dev-report-*.md' -ErrorAction SilentlyContinue
foreach ($r in $reports) {
    $content = Get-Content -Path $r.FullName -Raw -Encoding UTF8
    # 含改动方向词但无"对照 HEAD"约束
    if ($content -match '新增|删除|修改' -and $content -notmatch '对照 HEAD') {
        Write-Host "[WARN] $($r.FullName) 含改动描述但未以'对照 HEAD'开头"
    }
}
```

**通过判据**：
- 若无 dev-report 文件：N/A（跳过）。
- 若有 dev-report 文件且含改动方向词：必须至少 1 处含"对照 HEAD"。

**类别**：警告（语义检查较弱，首版仅做提示）。

**违反时的处理**：
- 不阻断 PR，提示 Dev 按 ES-002 §4.4 模板重写报告。
- 严重偏差（如 M1.1 那种"删 X"实为"加 Y"）由 Reviewer 人工复核 diff 后判定是否升级为阻断。

## 3. 通过/失败判据

| 门禁结果 | 判据 | 后续动作 |
|---|---|---|
| **全 PASS** | G7 / G8 PASS，G9 / G10 PASS 或 N/A | PR 可进入下一阶段 |
| **G7 或 G8 FAIL（阻断）** | 任一阻断规则失败 | PR **必须打回**，对应角色补落盘 / 清理 `$null` 文件 |
| **G9 或 G10 WARN（警告）** | 仅警告级失败 | 不阻断，但需在 case 归档时修正（Ops 负责追办） |

**重新跑规则**：修复后**必须重跑全部 G7–G10**，不可只跑失败项。

## 4. 可执行 PowerShell 脚本

### 4.1 使用方法

```powershell
# 在项目根执行
powershell -ExecutionPolicy Bypass -File .\docs\架构文档\质量门禁-产出物落盘.ps1
```

退出码语义：
- `0`：全部门禁通过（含警告项也通过——警告不阻断）
- `1`：至少一条阻断规则（G7 / G8）失败

脚本输出：每条规则打印 `[PASS]` / `[FAIL]` / `[WARN]` / `[N/A]`，最后打印汇总表。

### 4.2 脚本内容

> 完整脚本见同目录 `质量门禁-产出物落盘.ps1`（纯 ASCII，PS 5.1 兼容）。

### 4.3 脚本设计说明

- **纯 ASCII（强制）**：脚本内所有字符串（含注释）一律 ASCII，遵循 ES-002 §3.5（PS 5.1 默认 ANSI 读无 BOM .ps1 会乱码）。**本脚本是这条规范的活样本**——首版曾用中文字面量 `'docs\测试报告'` 导致 PS 5.1 把字符串读成 `docs\娴嬭瘯鎶ュ憡`，门禁完全失效；改为纯 ASCII（中文字符串用 `[char]0xXXXX` 拼装）后正常工作。
- **中文路径用 Unicode 代码点拼装**：脚本顶部用 `[char]0x6D4B + [char]0x8BD5 + ...` 拼 `测试报告` 等中文目录名，使 .ps1 文件保持纯 ASCII，运行时 PS 字符串是 UTF-16（正确还原中文）。
- **G7 文件大小校验**：除检查文件存在，还检查 Length > 100 字节，防止"只写标题的占位文件"绕过门禁。
- **G9 弱检测**：M1 阶段只能查乱码特征（`???` 或 `\xxx`），不能严格校验 UTF-8 编码（需读 `.git/COMMIT_EDITMSG` 原始字节，复杂度高）。M2 接 CI 后升级。
- **G10 N/A 处理**：M1.1 阶段无 dev-report 文件（Dev 报告输出在回复里），G10 返回 N/A 而非 FAIL，避免误报。
