### 2.2 分层规则（对齐先例，Reviewer 检查基线）

- **Controller 薄层**：参数接收→Service 调用→`R<T>` 返回；请求 DTO 内嵌 static class；不写业务校验（除"target 不能为空"级前置判空，AdrController:83 先例）。
- **Service 承载**：枚举/存在性/状态机/uk 兜底/审计/事务；`ServiceImpl<Mapper, Entity>` 继承 MP 基类；`BizException(400/404, msg)`。
- **tenant_id 只从 `TenantContext`/`LoginUser` 取**（ES-003 §9.3-4，G13）；实体继承 `BaseEntity`（雪花 id/审计五列/@TableLogic 自动填充）。

- **禁止**：`@InterceptorIgnore`（G13 BLOCKER）、请求参数传 tenant_id、代码中出现 team-* 字面量（G11）。

## 4. F3 到期拦截设计（商用硬伤修复，零 DDL）

### 4.1 共享判定核心：TenantSubscriptionService（eaiselp-data）

```java
public interface TenantSubscriptionService {
    /** 到期校验（登录/派生入口调用）：edition=trial 且 expire_time 非空 且 now>=expire_time
     *  → 抛 BizException(40003, "试用已到期，请联系平台升级：...")；trial 且 expire_time=NULL → WARN 日志后放行（Q4）；
     *  edition!=trial → 直接放行（expire_time 完全忽略，AC-F3.3）。 */
    void assertNotExpired(Long tenantId);            // 内部 selectById(t_tenant 主键单查，无缓存)
    /** 登录成功路径的临期提示（已查出的 Tenant 行直传，避免二次查询）。非 trial / NULL / (expire-now)>7×24h → 返回 null。 */
    TrialTip buildTrialTip(Tenant tenant);
}
```

`TrialTip`（放 eaiselp-common result 或 auth dto，随 LoginResponse 序列化）：

| 字段 | 类型 | 语义 |
|---|---|---|
| daysLeft | int | `N = ceil((expire_time − now) / 24h)`，向上取整（不满一天算 1 天；实现用 `Duration.toMillis()` 双精度除法后 `Math.ceil`） |
| level | String | `critical`（N=1，红色）/ `warning`（2≤N≤3，黄色）/ `normal`（4≤N≤7）——N=1 同时落在 (1,3] 区间，**红色优先**（PRD §4.3.1 三档定义） |
| expireTime | String | `yyyy-MM-dd HH:mm:ss` 原值回显 |

口径表逐条对齐 PRD §4.3.1（唯一权威）：到期判定 `now ≥ expire_time` 时刻精确含等于；提示窗口 `(expire−now) ≤ 7×24h`；`(expire−now) > 7×24h` 无提示。**本服务不做任何缓存**——恢复路径（改 edition/expire_time）后下一次登录/派生即生效（AC-F3.6"立即恢复"），主键单查对 P95 影响可忽略（PRD §6.5）。

### 4.2 登录拦截插入位（AuthServiceImpl.login，凭据校验后）

现行 9 步（AuthServiceImpl.java:44-107）：①查用户 → ②③密码（40001 防枚举）→ ④禁用（40002）→ ⑤查角色权限 → ⑥查租户 → ⑦签发 JWT → ⑧更新 last_login_at → ⑨返回。

**改造：④ 与 ⑤ 之间插入租户订阅校验，并把 ⑥ 的租户查询提前合并**：

```
④ 账户禁用 → 40002
④.5 [新] tenant = tenantMapper.selectById(user.getTenantId() ?? defaultTenantId)   // 原⑥提前，全链路仍只查一次
      subscriptionService.assertNotExpiredOf(tenant)      // 内部含 Q4 NULL 防御与 WARN
      → 到期：审计 login_trial_blocked（见下）+ 抛 BizException(40003, msg)
⑤ 查角色权限 → ⑦ 签发 JWT（trialTip = buildTrialTip(tenant) 塞入响应）→ ⑧ last_login_at → ⑨
```

- **防枚举顺序保持**（PRD §4.3.1）：到期校验在凭据校验**之后**——错密码 + 到期租户 → 仍 40001（QA 构造断言，AC-F3.1 后附口径）。
- **不签发 JWT、不更新 last_login_at**：④.5 抛出即中断，⑦⑧ 均未到达（AC-F3.1 Then 项）。
- **审计**：`auditService.log("login_trial_blocked", "tenant", String.valueOf(tenantId), {"tenantId":..,"username":..,"expireTime":..,"edition":"trial"}, "failure", msg)`——`resource_id=tenantId` 保证含 tenantId 可检索（登录时无 JWT，AuditService 的 claims=null 路径 tenantId 列兜底 0，故 tenantId 必须同时入 detail 与 resource_id，AC-F3.1 断言点）。AuthController 现有 catch 块的通用 `login_failure` 审计仍会补记一条（不冲突，AC 断言用 login_trial_blocked）。
- **message 文案**：必须含"试用已到期"字样 + 升级指引占位（如"试用已到期，请联系平台管理员升级（platform_admin 可通过订阅管理接口延期/转正）"）——前后端与 QA 以此断言。

### 4.3 派生前置校验（存量 JWT 24h 窗口补位，裁决附带约束 2）

两处入口，均在**参数校验之后、资源预占之前**插入 `subscriptionService.assertNotExpired(TenantContext.get())`：

| 入口 | 插入位 | 失败形态 |
|---|---|---|
| `POST /api/runtime/derive`（RuntimeController:80） | ①角色校验之后、②`createPending` 之前 | BizException(40003) → GlobalExceptionHandler → `R.fail(40003, msg)`；**不预占 pending 行、不烧 token** |
| `POST /api/runtime/orchestrate`（RuntimeController:148） | requirement 非空校验之后、`start()` 之前 | 同上；并补审计 `derive_trial_blocked` / `orchestrate_trial_blocked`（resource_type=tenant，detail 含 tenantId/username，failure） |

不选在 `DerivationEngine.derive` 内部校验的原因：异步线程内失败只能标任务 failed（token 可能已开始烧）；Controller 入口同步快速失败最省。`TenantContext` 在两处均有效（JWT 拦截器已注入）。

### 4.4 恢复路径（F3.3，platform_admin 专属）

`PUT /api/v1/tenant/{id}/subscription`（§5.6）：入参 `{edition?, expireTime?}`（null=不变，支持单字段更新）——edition 合法值 `trial/pro/enterprise/starter`（`@Value` 或常量集，非法 400，AC-F3.6）；expireTime 可空（置空=按 Q4 语义"未设置"）。写审计 `tenant_edition_change`（detail 含 `oldEdition→newEdition`、`oldExpireTime→newExpireTime`、操作者 username）。修改后无缓存直查（§4.1），**下次登录即生效**。本期无页面（curl/API 运营，UI 属 PRJ-006）。

## 本次经验沉淀

1. **多角色并行时 SE 动笔前先做"磁盘事实核对"**：本 case DBA 的 V6/H2 schema/数据库设计已先行落盘，SE 若按任务书假设"数据层待设计"重写一套表契约，将产生两份权威互相打架。SE 方案的第一节应是"磁盘上已有什么、评审结论是什么"，增量评审优于从零重写——先例对齐的对象不仅是代码，也包括同 case 其他角色的已落地产物。
2. **"拦截类功能"的工程四件套**：拦截点（登录+派生双点补位 token 烧刷口）+ 豁免矩阵（非 trial/NULL/凭据优先三重单测锁死）+ 恢复路径（无缓存直查=改库即生效 + 一行 SQL runbook）+ 误伤演练（QA 构造"被误拦的正式版"用例）。PRD 沉淀了"拦截必须带恢复路径"，工程侧应再补"误伤兜底 runbook"——拦截类功能上线前先回答"拦错了怎么 5 分钟内恢复"。
3. **存储侧迁移时 AC 要跟着翻译**：裁决把关联存储从门禁侧改到标准侧（Q1，Flyway checksum 硬约束驱动），但 PRD 的 AC 是按旧存储侧书写的——SE 有义务产出"断言翻译表"（§4.5）随方案下发 QA，否则验收阶段必然出现"实现正确但用例 FAIL"的假缺陷。今后凡裁决改变了 AC 的隐含前提，翻译表是 SE 方案的必备节。
