> 产出者：team-dba | 日期：2026-09-09 | 依据：PRD v1.0 §4/§5/§6 + 编排者裁决 Q1~Q6 + V4 r4/V7 幂等先例
> 迁移脚本：`eaiselp-runtime/src/main/resources/db/migration/V8__commercialization.sql`（交付物本体）
> 测试 schema：`eaiselp-runtime/src/test/resources/schema-h2.sql`（已同步追加 V8 段）
> 对 V1~V7 零改动（SHA256 哈希核对通过）。
> **计费口径以 PRD §4.4.1 B1~B6 为基线，Q6 裁决（首月按天折算）覆盖 B4**；权限矩阵以 PRD §4.9 为权威。

## 1. 存储选型决策矩阵

| 数据类型 | 推荐存储 | 理由 |
|---|---|---|
| 套餐目录 t_plan（商品资产，平台级 CRUD） | MySQL 8.0 既有库，平台级全局表 | 平台单一存储现状；量级 ≤ 几十行（商品目录非流水），CRUD + 审计即可；进 EaiselpTenantHandler.IGNORE_TABLES（同 t_permission 先例）——套餐是平台资产，与租户上下文无关 |
| 月度账单 t_invoice（租户级计费单据，强一致 + 幂等防重） | MySQL 既有库，租户级表 | 出账 = 定时事务写 + uk(tenant_id, period) 唯一约束兜底并发/重跑（AC-F2.7）；金额 DECIMAL 强类型；账单是收款依据单据，禁缓存降级（一致性优先） |
| 事故台账 t_incident（租户级轻量记录） | MySQL 既有库，租户级表 | 低频写、租户内轻量列表（P95 < 500ms），无独立存储诉求 |
| 租户-套餐绑定（裁决 Q1） | t_tenant 加 plan_code 列（不加关系表） | 单租户同一时刻至多绑一个生效套餐——1:1 关系独立成表是过度设计；加列沿用 V4 r2/r4 先例，最小 DDL 面；变更历史不建表（审计 + 账单快照已构成追溯链，裁决 Q1） |
| 套餐功能开关 / 账单明细快照 | JSON 列（非关系表） | features 结构稳定但键集可扩展（未知键忽略向前兼容）；detail 是纯快照（自洽、不参与关系查询）——V5/V6/V7 JSON 论证先例 |
| 用量事实源（账单聚合输入） | 零 DDL：复用 t_derivation 逐笔聚合 | B5 明确用量源 = t_derivation 成功终态逐笔 SUM；t_quota.token_used 仅实时水位，不作账单口径（PRD §4.4.1 原文），不冗余落账单前置表 |
| 出账金额计算 | Service 层 BillingCalculator（纯静态，裁决附带 #4） | 折算/超量/舍入口径先行锁定（L3 双计算器先例）；DB 只存结果列，不做生成列——无法表达"客户端提交值一律忽略"防伪造语义（V6/V7 同论证） |

## 2. 表清单（3 张新表 + 1 处加列）

### 2.1 t_plan 订阅套餐（15 列 = 9 业务 + tenant_id 占位 + 5 审计，平台级，F1.1）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id / tenant_id | BIGINT | PK / NOT NULL DEFAULT 0 | 雪花 ID / 平台级惯例占位（恒 0，同 t_permission） |
| code | VARCHAR(32) | NOT NULL，idx 列 | starter/pro/enterprise/custom（领域字典枚举，应用层校验非法 400，DB 不加约束——P6）；**不设 uk**：custom 可多份（AC-F1.2"名称不同即合法"），code 全局唯一会阻断合法第二份 custom；标准三档同 code 在架至多一份为应用层校验（PRD §4.1.1 契约原文） |
| name | VARCHAR(200) | NOT NULL，**uk_plan_name** | 套餐名全局唯一（PRD 契约；V4/V6/V7 uk(tenant,name) 的平台级变体）+ seed 幂等兜底 |
| monthly_price | DECIMAL(14,2) | NOT NULL | 月价（元）；≥0 应用层校验（负值 400，=0 合法=免费定制档 AC-F1.3）；**上限 99,999,999,999.99，Service 校验上限（L3 S1 教训镜像，裁决附带 #2）** |
| token_overage_price | DECIMAL(12,6) | NOT NULL | token 超量单价（元/千 token）；6 位小数支撑低单价——**B6/AC-F2.5 构造例 0.335 元/千 token 需 3 位以上小数，提示稿 DECIMAL(14,2) 会截断为 0.34 使应缴断言 101.00 失败，按 PRD §4.1.1 契约取 (12,6)**（冲突标注见 §7 R2） |
| features | JSON | NULL | {max_users, max_cases, token_limit, case_limit, derivation_limit, storage_limit_mb, layer_overrides:{strategy_enabled, program_project_enabled}, model_tiers:[...]}；服务端结构校验必需键与值域、未知键忽略；model_tiers 值域 = t_model_routing 档位名（opus/sonnet/haiku/reasoning/structured/mechanical/code，ES-003 §2.5） |
| sla_level | VARCHAR(16) | NOT NULL | bronze/silver/gold（必填，应用层校验枚举外/空 400——AC-F3.1）；承诺文案前端集中一处，纯展示不参与计算（§7-4/7-5） |
| enabled | TINYINT | NOT NULL DEFAULT 1 | 上下架：1=在架可被应用 / 0=下架不可应用（存量绑定租户不受影响——AC-F1.4）；对齐 t_architecture_principle/t_quality_gate_rule 的 enabled 先例，与 is_deleted 正交 |

**seed 官方三档**（id 101~103，占位定价、运营页面上改）：starter 299.00/12.00/bronze；pro 999.00/8.00/silver；enterprise 4999.00/6.00/gold。pro 的 token_limit=5,000,000 对齐 AC-F2.2 构造例（QA 可直接绑默认 pro 档构造数值断言）。

### 2.2 t_invoice 月度账单（19 列 = 12 业务 + 2 流转时间 + 5 审计，租户级，F2.1/F2.2/F2.3）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id / tenant_id | BIGINT | PK / NOT NULL | 雪花 ID / 租户隔离（拦截器自动过滤） |
| period | CHAR(7) | NOT NULL，**uk 列** | 账期键 yyyy-MM（自然月 `[当月1日00:00, 次月1日00:00)` Asia/Shanghai；恒 7 字符定长；值域与 t_quota.period 同构同源） |
| plan_code / plan_price | VARCHAR(32) / DECIMAL(14,2) | NOT NULL | 套餐快照（B1 月末快照=账期结束时刻生效套餐；月中升降级本期按期末档计价）；快照自洽，套餐后续改价/下架/逻辑删不影响已生成账单（AC-F1.4）；名称/超量单价/SLA 档入 detail JSON 五字段快照 |
| usage_tokens / overage_tokens | BIGINT | NOT NULL DEFAULT 0 | 本期成功派生 token 合计（成功终态计、失败/运行中不计；账期归属 started_at 缺失 fallback create_time——B5）/ 超额 = max(0, usage − token 配额基准)（B5） |
| overage_amount | DECIMAL(14,2) | NOT NULL DEFAULT 0.00 | 超量费 = ceil(overage_tokens/1000) × 超量单价快照（千 token 向上取整，不足 1 千按 1 千仅对超额部分——B5；构造例 8,016.00 AC-F2.2；ceil 边界 AC-F2.3）；**上限校验提示同上** |
| proration_amount | DECIMAL(14,2) | NOT NULL DEFAULT 0.00 | **Q6 裁决承载列**：首月按剩余天数折算的实收月费（月价 ÷ 当月天数 × 剩余天数含当天，HALF_UP 2 位）；仅"账期内首月新建即付费"租户非 0，其余 0.00=整月计费；trial 转正赠送当月不出账（B2/B3）不变 |
| total_amount | DECIMAL(14,2) | NOT NULL | 应缴 = **(proration_amount>0 ? proration_amount : plan_price) + overage_amount**，仅最终应缴 HALF_UP 2 位（B6：中间 BigDecimal 全精度；100.995→101.00 AC-F2.5）；服务端生成，客户端提交金额一律忽略（V7 防伪造先例）；**上限校验提示同上** |
| detail | JSON | NULL | 套餐五字段快照 + tokenUsed/tokenLimit/tokenOverageTokens/ktokenBilled/derivationCount/caseCount/storageUsedMb + Q6 折算参数（当月天数/剩余天数）；**平台内部成本 t_derivation.cost 禁入**（信息隔离 §6-3） |
| status | VARCHAR(16) | NOT NULL DEFAULT 'draft' | draft/issued/paid 单向顺次状态机（跳变/回退/paid 后流转 400——AC-F2.8，应用层校验 DB 不加约束）；draft 对租户不可见（AC-F2.9） |
| issued_time / paid_time | DATETIME | NULL | 流转审计时间落点（AC-F2.8 契约"时间落 issued_time/paid_time"；操作者走 t_governance_log 审计）。**任务列清单未列，按 PRD §4.4.2 契约与 AC-F2.8 断言补齐** |

**无 seed**：账单由出账逻辑运行时生成（定时 1 日 02:00 + 手动补生成，裁决 Q2），迁移不预置。

### 2.4 t_tenant 加列 plan_code（裁决 Q1，V4 r4 动态判断模式）

`plan_code VARCHAR(32) DEFAULT NULL`——引用 t_plan.code（逻辑外键，应用层校验；全库无物理外键风格）；NULL=未绑套餐（trial 不绑，AC-G2）；绑定/换绑仅经套餐应用（U2 扩展）一次性事务生效（AC-F1.5）。**information_schema 动态判断存储过程照抄 V4 r4**（1060 不致命，半污染库自愈）。

**存量回填 UPDATE**（PRD §4.1.2 / AC-G2 断言）：`SET plan_code = edition WHERE plan_code IS NULL AND edition IN ('starter','pro','enterprise') AND is_deleted=0`——幂等由 `plan_code IS NULL` 守卫（重放 no-op，人工换绑后永不被覆盖）；置于 t_plan seed 之后（回填值依赖同名默认套餐已存在）；trial/未知 edition 不绑（沿用拦截语义）。

## 3. 索引策略总表（按拦截器改写后真实 SQL 设计：租户侧 tenant_id 等值打头；平台侧通道不走拦截器故不含 tenant_id 前缀）

| 表 | uk | 二级索引 | 主查询路径论证 |
|---|---|---|---|
| t_plan | uk_plan_name(name) | idx_plan_code(code) | name 全局唯一（PRD 契约 + seed 兜底）；code 等值命中 t_tenant.plan_code 引用解析/套餐应用下拉（WHERE code=? AND enabled=1）。**code 不设 uk**：custom 可多份（AC-F1.2），标准档同 code 在架唯一属应用层校验。不加 (code,enabled)：目录 ≤ 几十行，残扫零成本 |
| t_invoice | uk_invoice_tenant_period(tenant_id, period) | idx_invoice_period_status(period, status) | uk 双职责：① 出账幂等防重（AC-F2.7 无第二行，定时+手动并发兜底）；② 租户费用中心历史账单 WHERE tenant_id=? ORDER BY period DESC（时间倒序=period 倒序）完全命中。二级索引服务**平台按 period 列表**（platform_admin 跨租户通道不走拦截器，故 period 打头；status 基数 3 低区分度放联合末尾）。不加 (tenant_id,status)：租户侧 issued/paid 筛选走 uk 前缀残扫（租户内 ≤ 数十行） |
| t_incident | —（无 uk，V1 t_derivation/t_checkpoint 无 uk 同例：台账无自然唯一键） | idx_incident_tenant_time(tenant_id, occurred_time) | 列表默认 occurred_time 倒序主查询（AC-F3.3）完全命中；恢复状态筛选 = recovery_time IS NULL 判空叠加扫描（判空不可索引等值优化，不建） |

## 4. 高并发策略

量级：≤200 租户 × 月账单 = ≤2,400 行/年（t_invoice）、事故台账租户内轻量、套餐目录 ≤ 几十行——**无读写分离/分库分表/缓存诉求**。出账定时任务错峰每月 1 日 02:00、线程池独立（裁决附带 #3，Dev 落地）；全量出账（200 租户 × 单租户 ≤5 万笔成功派生 SUM）< 60s（PRD §6-1）——聚合走 t_derivation 既有 (tenant_id, case_id)/(tenant_id, role) 索引由 SE 评估按需补 (tenant_id, status, started_at)（本期不动 V1 索引，防破坏 656 基线）。金额一致性：全程 BigDecimal（禁 float/double）、应缴服务端生成、uk 防并发重复出账（PRD §6-2）。

## 5. seed 与 ID 区间

- **权限原子 9 条：id 1081~1089**（V7 用毕 1080）：plan:view/create/edit、bill:view/bill:manage、cost:view、incident:view/create/edit。**以 PRD §4.9 权威矩阵 code 为准**——任务提示稿候选名 invoice:view/edit、fee:view 未采用（冲突标注 §7 R1）；bill:manage 单原子涵盖状态流转 + 手动补生成（裁决 Q2），比 invoice:view/edit 两分法少 1 原子且矩阵 18 行封顶（2203~2220 恰 18 行）。
- **授权行 18 行：id 2203~2220**：platform_admin×9（2203~2211，套餐+账单专属 1081~1085 仅此角色）、tenant_admin×4（2212~2215：cost:view + incident×3）、project_manager×3（2216~2218：incident×3，**无 cost:view——裁决 Q5 费用是管理层信息**）、engineer×1（2219：incident:view）、executive×1（2220：incident:view，**费用中心不可见——裁决 Q5**）。与 PRD §4.9 逐格一致（AC-G1）。
- **套餐 seed 3 行：id 101~103**（避开 V1 权限 1001~1031 与模型路由 1001~1009 的 1000+ 段；雪花 19 位永不碰撞）。
- 幂等：INSERT IGNORE（uk_permission_code / uk_role_perm / uk_plan_name 兜底）；AC-G2 重放行数不变。
- **V9 起从 1090 / 2221 续排**（已写入 V8 头注释）。

## 6. 迁移脚本与幂等性

- 结构：3×CREATE TABLE IF NOT EXISTS + 1×动态判断存储过程 ALTER（V4 r4 照抄：DROP/CREATE PROCEDURE + information_schema.COLUMNS 判空 + CALL + DROP 自清理）+ 1×守卫式回填 UPDATE + 4×INSERT IGNORE（套餐 3 行 / 权限 9 行 / 授权 18 行分 5 条语句）。
- 幂等面：任意半污染库重放自动收敛；重放 WARN（1050/1062/1305）预期无害。**唯一 UPDATE 以 `plan_code IS NULL` 守卫**，重放 no-op。
- 执行顺序契约：t_plan 建表 → 套餐 seed → t_tenant 加列 → 回填 UPDATE（依赖 seed 同名套餐已存在）→ 权限/授权 seed。
- 枚举合法性与状态机均应用层校验、DB 不加约束（V5/V6/V7 先例，PRD §0 P6）。
- 回滚：仅新增对象 + 一列 + seed，回滚 = DROP TABLE t_plan/t_invoice/t_incident + `ALTER TABLE t_tenant DROP COLUMN plan_code` + DELETE seed（permission 1081~1089 / role_permission 2203~2220 / plan 101~103）；生产不建议回滚，Flyway 不自带 down。
- H2 已同步：t_plan/t_invoice/t_incident 简化 DDL（DATETIME→TIMESTAMP、JSON→CLOB、TINYINT→INT、无 ENGINE/ON UPDATE/COMMENT）+ 4 索引 + **t_tenant 最小列集简化表（含 plan_code 直建——H2 此前无 t_tenant，无存量列场景不需动态判断 ALTER；生产结构以 V1+V8 为准）** + 套餐/权限/授权 MERGE INTO KEY(id)（与 V8 逐值一致，python 校验通过）。

## 本次经验沉淀

1. **金额精度由"构造例最小可表示值"倒推，不迁就提示稿口径**：超量单价若按提示稿 DECIMAL(14,2)，AC-F2.5 的 0.335 元/千 token 会在存储层被截断（0.34），最终断言 101.00 变 101.01——计费列宽度必须拿 PRD 构造例逐个代入验证可表示性，任何"看起来够用的两位小数"默认都要过这一关。
2. **uk 的归属要顺着"什么允许重复"推**：code 可重复（custom 多份）而 name 不可重复时，uk 落 name、code 落普通索引——把 uk 建在"枚举前缀"上会把应用层允许的合法多份数据变成 DB 报错；先枚举重复合法性矩阵再定 uk，与"区分度低不单独建索引"是同一思维的两面。
3. **裁决覆盖 PRD 口径时，承载列的语义要一次定死并在三处同步**（迁移头注释 / 列 COMMENT / 设计文档）：proration_amount 定义为"折算后实收月费（非折算=0.00）"而非"减免额（负数）"，total_amount 公式随之唯一化——若只留"折算金额"四个字，Dev/QA 会各自发明正负语义，数值断言口径分裂。
