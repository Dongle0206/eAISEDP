> 产出者：team-dba | 日期：2026-08-20 | 依据：PRD v1.0 §4/§6 + 编排者裁决 Q1~Q9 + V4 r4/V5 r2 幂等先例

## 1. 存储选型决策矩阵

| 数据类型 | 推荐存储 | 理由 |
|---|---|---|
| 工程标准/模板/资产/质量规则（结构化治理资产，CRUD+租户隔离+审计） | MySQL 8.0 既有库（新表） | 平台单一存储现状（CLAUDE.md 约定），强一致 + 租户拦截器复用；量级（≤1000/500/5000/5000 行/租户，PRD §6.5）远未到分库分表阈值（千万级） |
| 标准↔原则/门禁、资产↔标签 多选关联 | JSON 列（非关联表） | 纯展示级引用，无行级启停/独立生命周期诉求，JSON_CONTAINS 租户内扫描毫秒级——同 V5 ADR related_principle_codes 论证先例 |
| 到期拦截状态（edition/expire_time） | t_tenant 既有列 | F3 零 DDL 裁决（PRD 前置约束），不新建表不加列 |

## 2. 表清单（4 张新表，全部租户级业务表，不进 IGNORE_TABLES，不限层）

### 2.1 t_standard 工程标准（多版本行模型，裁决 Q7）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK | 雪花 ID |
| tenant_id | BIGINT | NOT NULL DEFAULT 0 | 租户隔离 |
| standard_code | VARCHAR(64) | NOT NULL，uk 列 | 标准编号（STD-NNNN 应用层生成可自定义） |
| title | VARCHAR(200) | NOT NULL | 标题 |
| version | VARCHAR(32) | NOT NULL，uk 列 | 版本号，同编号内不可重复 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'draft' | draft/published/deprecated，状态机应用层校验 DB 不加约束（V5 ADR 先例） |
| content | MEDIUMTEXT | NULL | 正文 markdown；**MEDIUMTEXT 纠偏**：PRD ≤20000 字符在 utf8mb4 下汉字约 80000 字节，超 TEXT 65535 字节上限 |
| related_principle_codes | JSON | NULL | 关联架构原则 code 多选（V5 先例） |
| related_gate_names | JSON | NULL | 关联门禁规则 name 多选（**裁决 Q1：关联放标准侧，不改已发布的 t_quality_gate_rule**，Flyway checksum 不可变） |
| deprecate_reason | VARCHAR(500) | NULL | 废弃原因（deprecated 必填，应用层校验） |
| 审计五列 | — | — | create_time/update_time/create_by/update_by/is_deleted |

- **uk_std_tenant_code_version (tenant_id, standard_code, version)**：PRD 契约 uk(tenant,编号,版本)——同编号同版本拒、同编号多版本行共存（AC-F1.1）；标准族版本时间线查询走 (tenant_id, standard_code) 前缀。standard_code 含租户自定义值，必须带 tenant_id。
- **idx_std_tenant_status (tenant_id, status)**：列表默认筛选 draft+published（AC-F1.2）。
- "同编号至多一个 published"由应用层发布事务保证（详见 §7 风险项 R1）。

### 2.2 t_template 模板库（单行当前版原地升版，裁决 Q7）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id / tenant_id | BIGINT | — | 同上 |
| template_type | VARCHAR(64) | NOT NULL，uk 列 | 开放字典（预置 5 值+自定义，应用层不枚举校验，PRD §0 P6 裁决） |
| template_name | VARCHAR(200) | NOT NULL，uk 列 | 名称 |
| version | VARCHAR(32) | NOT NULL | 原地升版：编辑时必须变更且 ≠ 当前值（应用层校验）；旧版本仅存审计 detail |
| content | MEDIUMTEXT | NULL | 正文 markdown，{{占位符}}；占位符清单不落库（详情实时提取，防双写不同步） |
| enabled | TINYINT | NOT NULL DEFAULT 1 | 启停（同原则/门禁先例） |

- **uk_tpl_tenant_type_name (tenant_id, template_type, template_name)**：同类型同名拒、跨类型同名合法（AC-F1.9 三例逐条对应）；类型筛选（含自定义值 AC-F1.10）走 uk 前缀。
- **不加 (tenant_id, enabled) 索引**：基数 2 区分度极差，≤500 行/租户前缀扫描毫秒级——V5 gate_result"按需加列不按需加索引"先例。

### 2.3 t_data_asset 数据资产目录

| 字段 | 类型 | 约束 | 说明 |

## 4. 高并发策略

单租户量级 ≤5000 行（PRD §6.5），无读写分离/分库分表/缓存诉求；四域列表分页走 uk 前缀，P95<500ms 无压力。登录链路到期校验为 t_tenant 主键单行查询，增幅可忽略。

## 6. 迁移脚本与幂等性

- V6 对既有表**零 ALTER / 零 UPDATE / 零存储过程**（F3 零 DDL：复用 t_tenant.edition/expire_time），仅 4×CREATE TABLE IF NOT EXISTS + 6×INSERT IGNORE——天然幂等，无 1060/1061 风险面（#20 教训的最彻底规避：不碰既有表）。
- 回滚：V6 仅新增对象，回滚=DROP TABLE t_standard/t_template/t_data_asset/t_data_quality_rule + DELETE seed（id 1059~1070 / 2134~2169）；生产不建议回滚，Flyway 不自带 down。
- H2 测试 schema 已同步（4 表简化 DDL + 权限 seed 用 MERGE INTO KEY(id) 幂等，对齐该文件既有风格；权限表此前未入 H2，本期起补齐供 AC-RBAC 类集成测试）。

## 7. 风险项

| # | 风险 | 缓解 |
|---|---|---|
| R1 | "同编号至多一个 published"无 DB 约束，应用层发布事务若漏加锁可能双 published | 发布事务内先 SELECT 旧 published（建议 FOR UPDATE）再取代；DB 侧可选兜底方案（生成列+条件唯一索引模拟）已论证并暂缓——引入生成列破坏零 ALTER 幂等简洁性，且发布是低频管理操作；QA 用例覆盖 AC-F1.4 |
| R2 | related_gate_names 存 name 引用门禁规则，规则改名/删除后 JSON 引用悬空 | 展示层"已删除/未找到"占位（同 AC-F1.7 删除占位语义）；打回展示不阻塞门禁判定（展示级打通） |
| R3 | 标签/关键字筛选走租户内扫描，资产 >5 万行后可能劣化 | 当前 ≤5000 行毫秒级；量级证明慢查询后再评估（生成列/关联表），预留本风险项跟踪 |
| R4 | 模板/标准旧版本仅存审计 detail，无版本回滚能力 | PRD 契约（§4.1.2/裁决 Q7）；回滚=从审计 detail 人工恢复，商用诉求出现时再立项 |
| R5 | H2 权限表为简化版（仅本 case seed 涉及列，无 uk） | 生产结构以 V1 为准；H2 仅测试装配用 |

## 本次经验沉淀

1. **字符宽度预算要按"最坏字节"算，不按字符数算**：PRD 写"≤20000 字符"时 TEXT（65535 字节）直觉够用，但 utf8mb4 汉字 3~4 字节/字下 20000 汉字≈80000 字节会写入失败/截断——正文类列一律 MEDIUMTEXT 起步（同 V5 VARCHAR(8) 存不下 FAIL_WARN 教训的泛化：契约长度 × 最大字节数 > 类型上限即升型）。
2. **零 ALTER 是幂等性的最强形式**：V4 r4/V5 r2 用 information_schema 动态判断兜住 ALTER 幂等，但存储过程+DELIMITER 本身引入新的失败面；当 case 范围本就不含既有表变更时，应显式在头注释宣告"零 ALTER"并把 F3 类需求压到纯应用层——幂等规范的最优解是"没有非幂等语句"，而非"给非幂等语句加防御"。
3. **"关联放哪侧"用迁移不可变性裁决**：跨表打通需求（标准↔门禁）两侧都能存 JSON，裁决依据之一是 Flyway checksum——已发布迁移的表（t_quality_gate_rule）一个字都不能改，关联自然落新表侧（t_standard.related_gate_names）；这条约束比建模偏好更硬，应作为跨表关联设计的先决检查项。
