### 0.3 冲突消解表（三处，必须随方案先行下发 QA/BA/UX/PO）

**（1）裁决 Q6 折算覆盖 PRD B4 首月整月（唯一实质冲突，任务已预告"以裁决为准"）**
- PRD 侧：B4"不按天折算（含月中新建即付费租户）"+ AC-F2.2 第二构造"8-20 新建即付费 → 同样出整月月价"。
- 裁决侧：Q6"首月按剩余天数折算（月价 ÷ 当月天数 × 剩余天数**含当天**，HALF_UP 2 位）；trial 转正赠送当月口径不变（B2/B3）"。
- **消解结论：以裁决为准**。B4 修读为"**非首个付费账期不折算**（期中升降级按期末档整月计价不变）"；B1~B3/B5/B6 不受影响。AC-F2.2 第二构造的 QA 断言改为：8-20 新建即付费绑 pro（月价 999.00）→ 8 月账单 base_fee = 999.00 × 12 ÷ 31 = 386.7096… → **386.71**（剩余天数含 20 日当天 = 12 天，8 月 31 天，先乘后除 HALF_UP 2 位，D-11）。SE 已按裁决实现折算；**请 PO 出 PRD v1.1 勘误同步 B4 措辞与 AC-F2.2 构造**（本方案先行，不停等勘误）。
- 折算判定口径（裁决未细化，SE 冻结，D-11）：账期起始时刻（当月 1 日 00:00）**租户不存在**（`t_tenant.create_time ≥ 当月 1 日`）且出账时为付费版（edition ≠ trial）→ 该账期按折算计费；剩余天数 = 当月天数 − create_time 日号 + 1（**含创建当天**）；折算基准 = B1 期末套餐月价；超量费不折算（按实际用量 B5）；优先级 B2/B3 > 折算（凡 trial 相关不出账场景优先命中）。trial 起步后转正的租户走 B3 赠送（create_time 在期初之前或期内 trial 转正，均不折算——B3 赠送优先）。

**（2）B3 期初状态判定的数据源与 fallback（PRD 留白"审计或订阅历史表，Q1"，裁决 Q1 定审计）**
- 判定实现：查询 `t_governance_log`（action=tenant_edition_change，resource_type=tenant，resource_id=tenantId）中**账期起始时刻之后**该租户首个 `trial→非trial` 变更——存在且变更时间 ∈ 账期 → 期初为 trial → B3 赠送不出账。
- fallback（审计缺失的脏数据防御，SE 冻结）：无任何相关审计记录时——出账时 edition=trial → 按 B2 不出账；出账时付费且 `create_time < 账期起始` → 视为期初已付费（正常出账，整月或按 D-11 折算）。两分支都保守向"少收不误收"倾斜，WARN 日志记录 fallback 命中。

**（3）租户列表页磁盘事实（PRD F1.3 假设存在，实际不存在）**
- PRD F1.3"租户列表页改造：行内「订阅变更」操作"——磁盘事实：`eaiselp-web-separate/pages/` **无 tenant-list.html**（37 页清单已核，租户管理仅有 layer-settings/llm-key 两局部页）。
- **消解结论：新建最小 `pages/tenant-list.html`**（租户列表 + U1 订阅快照列 + 行内「订阅变更」弹窗），作为本 case 范围增量向编排者/UX 报备；否决"订阅变更并入套餐管理页反向选租户"——违背 US-2"租户列表行内操作"语义。后端零增量（列表数据走既有 TenantController 通道或 U1 聚合，见 §5 注）。

## 4. 计算引擎设计（唯一实现口径；QA 构造值照 PRD §4.4.1 + 裁决 Q6）

### 4.1 BillingCalculator（静态纯函数，data/service/subscription）

```java
public final class BillingCalculator {
    /** 超额 token = max(0, tokenUsed − tokenLimit)。 */
    public static long overageTokens(long tokenUsed, long tokenLimit);
    /** 计费千 token 单位数 = overage ≤ 0 ? 0 : (overage + 999) / 1000（整数运算即 ceil，无浮点）。 */
    public static long ktokenBilled(long overageTokens);
    /** 超量费（全精度）= ktokenUnits × unitPrice（BigDecimal 乘法，不预舍入——B6 中间不舍入）。 */
    public static BigDecimal overageFeeRaw(long ktokenUnits, BigDecimal tokenOveragePrice);
    /** 超量费落库值 = overageFeeRaw HALF_UP 2 位（D-4 恒等式左元）。 */
    public static BigDecimal overageFee(long ktokenUnits, BigDecimal tokenOveragePrice);
    /** 首月折算基础费 = monthlyPrice × remainingDays ÷ daysInMonth（先乘后除），HALF_UP 2 位（D-11/裁决 Q6）。 */
    public static BigDecimal proratedBaseFee(BigDecimal monthlyPrice, int daysInMonth, int remainingDays);
    /** 应缴 = (baseFee + overageFeeRaw) HALF_UP 2 位；并做 DECIMAL(14,2) 域上限校验（超限抛 BizException 指名，D-4 镜像）。 */
    public static BigDecimal amountDue(BigDecimal baseFee, BigDecimal overageFeeRaw);
}
```

## 12. 本次经验沉淀

1. **"裁决改口径"必须产出消解表并改写 QA 构造值，不能只写"以裁决为准"**：Q6 折算覆盖 B4 后，AC-F2.2 的第二构造（8-20 新建→整月）在裁决下是**错误断言**——若方案只引用裁决原文而不给出 386.71 的完整计算链（剩余天数含当天/当月天数/先乘后除/HALF_UP），Dev 与 QA 会在"剩余天数含不含创建当天"这类细节上各自发明口径。裁决一句话 → SE 必须展开为"判定条件 + 优先级 + 公式 + 边界例"四件套才可下发。
2. **既有端点扩展的兼容设计锚点是"分叉点唯一化"**：U2 扩展 planCode 时把新旧行为的分叉收敛到"入参 planCode 是否为空"一个判断上（互斥 400 挡住灰地带），存量路径代码零穿过新逻辑——比"新旧逻辑交织但都覆盖测试"可靠一个数量级，回归面从"全部用例"缩到"分叉点单测"。
3. **平台级批处理任务复用"tenant 0 = SYSTEM"通道是零侵入的**：定时出账与 platform_admin 跨租户操作天然同源（TenantContext 缺省 0 → 拦截器全放行 → 实体显式 tenant_id），不需要 @InterceptorIgnore（G13 红线）也不需要独立数据源——这个模式应沉淀为平台惯例：**凡跨租户批处理，一律 SYSTEM 上下文 + 显式租户传参 + 禁依赖 ThreadLocal**。
