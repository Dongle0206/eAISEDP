# 编排者裁决记录 — case-20260820-L2治理收口

> 裁决人：team-orchestrator | 日期：2026-08-20 | 依据：PRD v1.0 开放问题 Q1~Q9
> 原则：优先对齐平台既有先例（V4/V5、ADR/雷达模式），不自创新约定。

## 裁决

| Q | 议题 | 裁决 | 依据 |
|---|------|------|------|
| Q1 | 表名与门禁-标准关联存 code 还是 id | 表名：`t_standard` / `t_template` / `t_data_asset` / `t_data_quality_rule`。关联放**标准侧**：`related_principle_codes` / `related_gate_names` JSON 数组——**不改已发布的 t_quality_gate_rule** | ADR `related_principle_codes` 先例；已发布迁移不可改（Flyway checksum） |
| Q2 | 敏感等级英文码 | `public/internal/sensitive/confidential` | 业界惯例（四档对齐 PRD 中文枚举） |
| Q3 | 到期后存量 JWT 24h 窗口 | **接受**。JWT 无主动吊销能力，24h=access token TTL 现实；恢复路径（edition 改正式版）即时生效 | 现有 JWT 架构不为本需求引入 Redis 黑名单 |
| Q4 | expire_time=NULL 防御语义 | 非 trial：NULL=永久有效；trial：NULL 视为不过期（数据异常不锁死客户，登录时记 WARN 日志） | 可靠性原则：防御性默认不伤客户 |
| Q5 | 质量规则关联与阈值 | 单资产关联（多资产拆多条规则）；阈值百分比 0~100 | 简单优先，PRD Q5 建议采纳 |
| Q6 | standards/steward 角色缺位 | tenant_admin 兼任（全量），PM/engineer/executive 只读 | V5 Q5 先例（EA 缺位由 tenant_admin 兼任） |
| Q7 | 模板 vs 标准版本模型 | **模板原地升版**（一个模板一个当前态，版本号自增，变更写审计——技术雷达先例）；**标准多版本**（每编号每版本一行，同编号唯一 published，发布新版自动 deprecated 旧版） | 两者生命周期本质不同：模板是"当前可用资产"，标准是"演进治理文档" |
| Q8 | 机密资产元数据对 engineer 可见 | engineer 只读可见（含敏感等级标记）。敏感等级是元数据非数据本体；目录的价值在于让工程师知道"有什么、多敏感、找谁" | ADR/雷达 engineer view 先例 |
| Q9 | 到期错误码 | `40003`（业务错误：试用已到期），临期提示走登录响应扩展字段非错误 | 错误码段 40001+ 业务错先例 |
