## 1. 背景与目标

### 1.1 业务背景

**（A）L2 治理剩两块无平台承载。** PRJ-003 主体（DORA/里程碑/依赖）与 PRJ-004 拆分项（ADR/雷达）已于 case-20260818 交付，L2 治理九宫格还差两块：

- **工程标准靠 markdown 人肉维护**：体系自身的工程标准（如 ES-001/002/003）散在 docs/架构文档/ 下，商用客户的租户级工程标准没有任何系统承载——标准没有编号/版本/生命周期，"哪条标准现行有效"说不清；标准与门禁规则完全脱节，门禁打回时说不出"违反了哪条标准"，标准成了墙纸。
- **模板资产无库**：PRD/技术方案/任务清单/测试用例等模板靠口口相传或个人拷贝，版本混乱；未来 L1 编排要按模板生成初稿，没有模板库就没有注入源。
- **数据家底不清**：企业客户有哪些数据资产（库/表/接口/报表/文件）、谁负责、多敏感，没有目录；数据质量问题（不完整/不准/不一致/不及时）靠事后救火，没有规则化的登记与追踪。team-standards / team-steward 两个 L2 角色至今"有方法论、无平台落点"。

**（B）试用到期无拦截是商用硬伤。** 代码级现状证据：

- `TenantController.register()`（eaiselp-runtime TenantController.java:73-80）创建租户时写 `edition='trial'`、`expire_time=now+30d`；
- `AuthServiceImpl.login()` 校验用户存在/密码/账户禁用后直接签发 JWT（AuthServiceImpl.java:44-107），**全链路（登录/currentUser/派生/编排）无任何 expire_time/edition 校验**；
- 平台亦无修改 edition/expire_time 的任何接口（TenantController 仅有 register + llm-key）。

后果：**试用租户永不过期**，30 天试用承诺形同虚设，直接侵蚀商用转化路径（PRJ-006 前置）；且一旦加了拦截而没有恢复路径，到期租户将被永久锁死（无接口可延期/转正）。

## 2. 用户故事（INVEST 原则）

### US-1 标准负责人（team-standards 角色落点，本期由 tenant_admin 兼任，见 Q6）

- 作为「标准负责人」，我希望「维护带编号/版本/状态（draft→published→deprecated）的工程标准，发布新版本时旧版本自动废弃」，以便「任何时点"现行有效的是哪个版本"一目了然，不再靠问人」。
- 作为「标准负责人」，我希望「把标准与架构原则多选关联、与门禁规则多选关联」，以便「标准不是孤岛——原则给方向、标准给细则、门禁给执行力，三者互相索引」。

### US-2 门禁管理员（tenant_admin 兼任）

- 作为「门禁管理员」，我希望「配置门禁规则时关联 published 状态的标准，Case 被该规则打回时能看到"依据标准 STD-xxx"」，以便「打回有据可依，工程师知道去读哪条标准，而不是觉得门禁在刁难」。

### US-3 模板管理员（tenant_admin 兼任）

- 作为「模板管理员」，我希望「按类型（PRD/技术方案/任务清单/测试用例/部署方案…）管理模板，正文支持 {{占位符}} 并展示提取清单，可启停」， 以便「为未来 L1 编排按模板生成初稿备好结构化注入源（本期内只管理、不注入）」。

### US-4 数据管家（team-steward 角色落点，本期由 tenant_admin 兼任，见 Q6）

- 作为「数据管家」，我希望「登记数据资产（所属系统/类型/责任人/敏感等级/标签）并按敏感等级与标签筛选」，以便「企业数据家底一张清单，谁是责任人、哪里是机密一目了然」。
- 作为「数据管家」，我希望「给资产挂质量规则（完整性/准确性/一致性/及时性 + 阈值），手动登记最近检查结果」， 以便「数据质量问题有台账、有追踪，不再靠救火记忆」。

### US-5 试用客户管理员（tenant_admin，trial 租户）

- 作为「试用客户管理员」，我希望「试用临期时登录能看到剩余天数提示，到期后登录得到明确的"试用已到期"报错，正式版不受任何影响」， 以便「清楚知道试用边界，不会被莫名锁死也不会被永久白嫖遗忘」。

### US-6 平台运营（platform_admin）

- 作为「平台运营」，我希望「把到期试用租户的 edition 改为正式版或延长 expire_time，改完该租户立即可登录」， 以便「销售签约后即时开通，不需要 DBA 手工改库」。

### US-7 高管/项目经理/工程师（只读消费方）

- 作为「工程师」，我希望「只读查阅现行工程标准与可用模板」， 以便「写方案前先对齐标准，用模板起稿不跑偏」。
- 作为「高管」，我希望「只读查看数据资产目录的敏感等级分布与质量规则通过情况」， 以便「数据合规风险有量化视图」。

**INVEST 自检**：每个故事独立可验收（对应 §5 各 AC）；可协商（页面形态可由 UX 调整，状态机/口径/权限矩阵不可）；对七类角色各自有价值；规模适合单 story；可测（AC 全部 Given-When-Then 且含构造数值）；时间盒在本 Case 内。

## 4. 功能需求详述

### 4.1 F1 标准库管理

#### 4.1.1 工程标准（F1.1）

**数据契约（语义，SE 定稿表名/列名）**：编号（默认 STD-NNNN 应用层生成，可自定义）/ 标题 / 版本（VARCHAR，同编号内不可重复）/ 状态 / 正文（markdown，建议 ≤20000 字符）/ 关联架构原则（**多选，存原则 code 的 JSON 数组**，同 V5 ADR related_principle_codes 先例）/ 废弃原因（deprecated 时必填）。唯一键：**(tenant_id, 编号, 版本)**；辅助索引建议 (tenant_id, 状态) 列表默认筛选。

**状态机（应用层校验，非法流转 400，同 ADR 先例）**：

```
draft ──发布──> published ──废弃(必填原因)──> deprecated（终态）
draft ──作废(必填原因)──> deprecated
其余流转（deprecated→任何、published→draft 等）一律 400
```

**多版本取代语义（本 PRD 裁决，区别于 ADR 单记录模式）**：标准是合规资产，发布版本必须不可变——同一编号允许多版本行共存（v1.0 deprecated 与 v2.0 published 并存可追溯）；**发布同编号新版本时，原 published 版本自动流转 deprecated（废弃原因=「被 {code} {新版本} 取代」），任何时点每个编号至多一个 published 版本**；全程写审计（发布、自动废弃各一条）。

**引用规则（"published 才可被引用"的引用面）**：门禁规则关联标准的选择器**仅列出 published 状态标准**（AC-F1.3/F1.7）；draft/deprecated 标准在列表中可见（历史追溯，列表默认筛选 draft+published，同 ADR 列表默认 proposed+accepted 先例）但不可被选择关联。

**编辑限制**：draft 可编辑全部字段；published/deprecated 只读（变更=废弃后建新版本，或对 published 直接建同编号新 draft）；删除一律逻辑删（is_deleted），删除后门禁侧关联条目展示"已删除"占位、**不影响门禁运行**（关联是展示级打通，门禁判定不依赖标准存在，AC-F1.7）。

**关联架构原则**：可空多选，值域 = 租户内 t_architecture_principle.code（存在性校验，无效 code 400）；列表支持按关联原则筛选（JSON_CONTAINS，量级 §6.2，无需专索引——同 V5 ADR 论证）。

#### 4.1.2 模板库（F1.2）

**数据契约（语义）**：模板类型（**开放字典**：前端预置 PRD/技术方案/任务清单/测试用例/部署方案 5 个常用值 + 允许自由输入自定义；应用层不枚举校验，防 P6 硬编码）/ 名称 / 版本（VARCHAR）/ 正文（markdown，支持 `{{标识符}}` 占位符，标识符限字母数字下划线）/ 启用状态（enabled，同原则/门禁先例）。唯一键：**(tenant_id, 类型, 名称)**——模板是**单行当前版**模型：版本是字段、原地升版（编辑正文时版本号必须变更且 ≠ 当前值，不比较大小；旧版本内容仅存审计 detail），**与标准的多版本行模型有意不同**（模板是操作资产、标准是合规资产，Q7 请 SE 评审确认）。

**占位符**：保存时提取正文中所有合法 `{{id}}` 占位符并在详情展示清单（如 `project_name, case_id`）；无占位符的模板合法（占位符可选）；本期只存储与提取展示，**不做注入**（§7-1）。

**启停**：停用模板列表默认隐藏（筛选可见）、详情标注"已停用"；本期内启停无编排行为影响（AC-F1.12 断言仅管理面）。

#### 4.1.3 标准-门禁打通（F1.3）

- **关联方向与存储**：关联关系挂在**门禁规则侧**（推荐存标准 code 的 JSON 数组——code 标识标准族，展示时解析其当前 published 版本，自动跟随版本取代；最终契约 SE 定，Q1）。关联时只允许选 published 标准（选择器过滤 + 提交校验双重保险，提交 draft/deprecated 的 code → 400）。
- **双向可见**：门禁规则详情/编辑页展示关联标准（编号/标题/当前 published 版本）；标准详情反向展示"被哪些门禁规则引用"列表。
- **打回展示（本期"打通"的最小闭环）**：Case 详情/编排步骤的**门禁 FAIL 打回原因旁展示"依据标准：{编号}《{标题}》{版本}"**——展示层按 steps_json 的 gateRuleId 动态查规则关联标准渲染，**不改 steps_json 结构、不改门禁判定逻辑**（AC-F1.8）。
- **引用粒度**：本期引用粒度=「标准（编号+版本）」；条款级锚点（如 STD-0001§3.1）由关联时的备注自由填写，结构化条款拆分为范围外（§7-8）。
- 更深打通（标准正文自动注入 Reviewer 门禁上下文）为未来 PRJ 范围（§7-1）。

### 4.2 F2 数据治理

#### 4.2.1 数据资产目录（F2.1）

**数据契约（语义）**：资产名称 / 所属系统（自由 VARCHAR）/ 资产类型（枚举 database/table/api/report/file，应用层校验非法 400）/ 责任人（自由 VARCHAR，本期不联动 t_user，Q 无）/ 敏感等级（枚举 public/internal/sensitive/confidential 四档，Q2）/ 描述 / 标签（JSON 数组，自由值，随录入自然扩展，无独立标签管理页）。唯一键：**(tenant_id, 所属系统, 资产名称)**——同系统同名资产不可重复登记。

#### 4.2.2 数据质量规则（F2.2）

**数据契约（语义）**：规则名（uk：租户内唯一，同门禁规则 uk_gate_tenant_name 先例）/ 关联资产（**单选** t_data_asset.id，存在性校验无效 400；是否需多资产见 Q5）/ 检查类型（枚举 completeness/accuracy/consistency/timeliness）/ 阈值（DECIMAL(5,2)，语义=百分比达标线 0~100，如 ≥99.5；登记人按检查类型解释，展示附 %，Q5）/ 最近检查结果（结果 pass|fail + 实测值 DECIMAL 可选 + 检查时间 DATETIME 登记时可选默认当前 + 备注）。

**手动登记语义（本期不做自动探测，§7-2）**：每次登记**覆盖**最近检查结果字段（单值当前态，不落历史行——历史唯一留痕 = t_governance_log 审计 detail，同 V5 雷达环移动先例）；pass/fail 由登记人判定，平台不做阈值自动判定（§7-5）。

### 4.3 F3 试用到期拦截（商用硬伤修复，零 DDL）

#### 4.3.1 到期判定与临期提示口径（唯一权威，QA 照此构造）

| 口径项 | 定义 | QA 构造示例（设登录时刻 T） |
|---|---|---|
| **到期判定** | 当前时刻 `now ≥ expire_time` 即到期（时刻精确，含等于） | expire_time = T−1s → 到期 |
| **豁免规则** | 仅 `edition = 'trial'` 的租户执行到期校验；edition ≠ trial（pro/enterprise/starter 等）**即使 expire_time 已过也不拦截、不提示** | edition=pro 且 expire_time=T−30d → 正常登录 |
| **NULL 防御** | trial 且 expire_time 为 NULL → 视为未设置到期，不拦截不提示（注册恒写 +30d，此为脏数据防御，Q4 确认） | expire_time=NULL → 正常登录 |
| **提示窗口** | 未到期且 `(expire_time − now) ≤ 7×24h` → 登录成功响应携带试用提示（含剩余天数） | expire_time=T+7h → 提示"剩 1 天" |
| **剩余天数 N** | `N = ceil((expire_time − now) / 24h)`，向上取整（不满一天算 1 天） | expire_time=T+7×24h−1h → N=7 |
| **无提示边界** | `(expire_time − now) > 7×24h` → 无提示 | expire_time=T+8×24h → 无提示 |
| **7/3/1 三档** | N∈(3,7] 常规提示 / N∈(1,3] 黄色警示 / N=1 红色强提示（文案与形态 UX 定，AC 断言 N 值与提示出现） | N=3 → 黄档 |
| **拦截报错** | 登录失败，业务错误（错误码语义=试用已到期，建议 40003，SE 定稿；**message 文案必须含"试用已到期"字样及联系升级指引占位**），不签发 JWT、不更新 last_login_at | — |
| **防枚举顺序** | 到期校验发生在**凭据校验通过之后**（凭据错误 + 到期租户 → 仍报"用户名或密码错误"，不泄露租户状态） | 错密码 + 到期租户 → 40001 |
| **拦截范围** | 本期拦截点=登录接口；存量已签发 JWT（24h 有效期）自然过期失效，不做请求级全量校验（§7-7，Q3） | — |

#### 4.3.2 到期状态可见性（F3.2）

- **全员**：临期提示随登录成功响应返回，前端登录后/工作台顶部展示提示条（剩余天数文案）。
- **tenant_admin**：租户设置页新增"订阅状态"区（edition 展示名 + expire_time + 剩余天数/已到期标识）；数据源为租户状态查询 API，**该 API 仅 tenant_admin/platform_admin 可访问**（应用层角色校验，无新增权限原子，与 llm-key 端点同模式），其他角色 403。
- 注册行为不变：仍写 edition='trial' + expire_time=now+30d（本 Case 只加校验，不改注册）。

#### 4.3.3 恢复路径（F3.3，P1）

platform_admin 专属管理 API：修改指定租户的 edition（trial→正式档）或 expire_time（延期）；入参校验（edition 合法值、expire_time 可空）；**写审计**（action=tenant_edition_change，detail 含旧值→新值与操作者）；修改后该租户用户立即恢复正常登录（下次登录即生效，AC-F3.6）。本期内不提供页面（curl/API 即运营操作，UI 属 P2/PRJ-006）。

## 5. 验收标准（Given-When-Then，31 条）

### F1 标准库

**AC-F1.1 标准创建与多版本唯一性**
- **Given** 租户 A 的 tenant_admin 已登录
- **When** 创建标准 {编号 STD-0001, 版本 v1.0, 标题 T, 正文 B, 状态 draft} → 成功（200）；再创建 {STD-0001, v1.0} 同编号同版本 → 被拒（唯一冲突业务错误）；再创建 {STD-0001, v2.0} → 成功
- **Then** 列表可见 STD-0001 两条版本行；默认编号未填时应用层生成 STD-NNNN 且租户内不重复

**AC-F1.2 标准状态机**
- **Given** STD-0001 v1.0 处于 draft
- **When** 依次执行 draft→published → 成功；published→deprecated（填废弃原因"被取代"）→ 成功；deprecated→published → 被拒（400 非法流转）；published→draft（另建一条 published 数据验证）→ 被拒（400）；published→deprecated 未填原因 → 被拒（400）
- **Then** 每次合法流转写一条审计（action 含状态变化与操作者）；列表默认筛选为 draft+published（deprecated 需显式筛选可见）

**AC-F1.3 published 才可被引用**
- **Given** 租户 A 存在 STD-0001 v1.0（draft）、STD-0002 v1.0（published）、STD-0003 v1.0（deprecated）
- **When** 打开门禁规则编辑页的关联标准选择器
- **Then** 选择器仅列出 STD-0002；直接提交含 STD-0001 或 STD-0003 code 的关联请求 → 400

**AC-F1.4 发布新版自动取代**
- **Given** STD-0001 当前 published 版本为 v1.0
- **When** 创建 STD-0001 v2.0（draft）并执行发布
- **Then** v2.0→published 成功，且 **v1.0 自动流转 deprecated**（废弃原因含"被 STD-0001 v2.0 取代"字样）；STD-0001 此刻 published 版本**有且仅有一个**；审计新增两条（v2.0 发布、v1.0 自动废弃）

**AC-F1.5 编辑与只读限制**
- **Given** STD-0001 v1.0（draft）与 STD-0002 v1.0（published）
- **When** 编辑 draft 的正文 → 成功；编辑 published（或 deprecated）的任意字段 → 被拒（业务错误提示"发布后不可编辑，请升版"）
- **Then** 逻辑删除 published 标准成功后，列表不可见、审计留痕

**AC-F1.6 关联架构原则**
- **Given** 租户 A 存在架构原则 P3/P11
- **When** 编辑 draft 标准关联原则为 ["P3","P11"] → 成功且详情回显两条；提交 ["P3","P99"] → 400（P99 不存在）；提交空数组/不填 → 成功（可空）
- **Then** 标准列表按原则 P3 筛选可命中该标准（未关联 P3 的标准不出现在结果中）

**AC-F1.7 标准-门禁双向关联与删除占位**
- **Given** 门禁规则 R（t_quality_gate_rule 既有数据）与 published 标准 STD-0002
- **When** 给 R 关联 STD-0002 → 成功；R 详情展示"STD-0002《标题》v1.0"；STD-0002 详情"被引用"区展示 R；随后逻辑删 STD-0002
- **Then** R 详情关联条目变为"已删除"占位；**R 的门禁判定行为不变**（编排打回/放行逻辑零变化——SE 用既有编排用例回归）

**AC-F1.8 门禁打回展示依据标准**
- **Given** 规则 R 已关联 STD-0002，且存在一个因 R 而 FAIL 打回的编排步骤（steps_json 含 gateRuleId=R）
- **When** 打开该 Case 详情查看该步骤打回原因
- **Then** 打回原因旁展示"依据标准：STD-0002《标题》v1.0"；R 未关联任何标准时，该展示区不出现（不显示空占位）

### F3 试用到期拦截

**AC-F3.1 到期登录拦截**
- **Given** trial 租户 T 的 expire_time = 昨日 12:00，其用户 u（凭据正确、账户 active）
- **When** u 调用登录接口
- **Then** 登录失败：业务错误码语义=试用已到期（建议 40003，SE 定稿），message 含"试用已到期"字样与升级指引占位；响应不含 token；last_login_at 未更新；t_governance_log 留拦截审计（含 tenantId/username）

**AC-F3.2 临期提示口径（数值断言，登录时刻 T）**
- **Given** 四个 trial 租户 T8/T7/T3/T1 的 expire_time 分别为 T+8×24h、T+7×24h−1h、T+3×24h−1h、T+7h
- **When** 各自用户凭据正确登录
- **Then** T8：登录成功且响应**无**试用提示；T7：成功+提示剩余 **7** 天；T3：成功+提示剩余 **3** 天（黄色档）；T1：成功+提示剩余 **1** 天（红色档）；四例登录响应均含 token；前端登录后提示条文案含对应剩余天数

**AC-F3.3 正式版豁免**
- **Given** 租户 edition=pro（另测 enterprise/starter 各一），expire_time = 30 天前
- **When** 其用户登录
- **Then** 登录成功、无任何试用提示/拦截（expire_time 被完全忽略）

**AC-F3.4 NULL 防御**
- **Given** trial 租户 expire_time=NULL（DB 直改构造）
- **When** 其用户登录
- **Then** 登录成功、无提示、无拦截（Q4 确认后如改口径同步修订本 AC）

**AC-F3.5 到期状态可见性**
- **Given** trial 租户剩余 5 天
- **When** tenant_admin 打开租户设置页
- **Then** "订阅状态"区展示 edition=试用版、expire_time 原值、剩余 5 天；engineer 调用该租户状态查询 API → 403；登录提示条对该租户**全部角色**用户可见（AC-F3.2 提示随登录响应全员返回）

**AC-F3.6 恢复路径（P1）**
- **Given** 租户 T 已到期（AC-F3.1 状态被拦）
- **When** platform_admin 调用管理接口将 T 的 expire_time 延至 +30d（或 edition 改为 pro）
- **Then** 修改成功且审计含旧值→新值；随后 T 的用户登录成功（AC-F3.1 不再触发）；tenant_admin 调用该管理接口 → 403；edition 传非法值 → 400

## 6. 非功能需求

1. **多租户隔离（P11，阻断级）**：四张新表带 tenant_id、不进 IGNORE_TABLES、全查询走租户拦截器；禁止 @InterceptorIgnore（G13 BLOCKER）。
2. **迁移幂等与升级兼容**：V6 建表 IF NOT EXISTS、seed INSERT IGNORE；零 ALTER（无既有表变更，天然规避 1060 类部署故障——V4 r4/V5 r2 教训延续）；存量租户与新建租户行为一致（权限为系统级 seed，无需按租户 provisioning）。
3. **接口规范（G14）**：新增 API 全部 `/api/v1/` 前缀；Controller 从 TenantContext/LoginUser 取 tenant_id，不从请求参数取（防伪造，ES-003 §9.3-4）。
4. **零硬编码（P6/G11）**：四组领域枚举按 §0 裁决处理（数据字典枚举应用层校验；模板类型开放字典不校验）；前端枚举文案集中一处定义。
5. **性能**：单租户量级假设——标准 ≤1000 行（含历史版本）、模板 ≤500、资产 ≤5000、质量规则 ≤5000（对齐 V5 §6.2 量级口径）；四域列表均分页，列表接口 P95 < 500ms（与既有 29 页面同水位）；登录链路新增到期校验为单行主键查询，登录耗时增幅可忽略（QA 对比基线 ±50ms 内）。
6. **安全**：到期校验顺序保持防枚举语义（§4.3.1）；四域无对外白名单接口（全部需 JWT）；敏感等级为元数据标注，本期不做行级可见性/脱敏（§7-9）。
7. **兼容性**：前端延续 jQuery + Bootstrap 5 独立页面、无构建；页面数 29→33；既有页面（gate-rule/case-detail/租户设置）仅增量改造，不影响存量功能。
8. **国际化**：项目无 i18n 约定（CLAUDE.md 未列语言清单），本期与现状一致采用中文文案；i18n 框架引入属平台级决策，不入本 Case。
9. **审计与可追溯**：AC-AUDIT.1 全覆盖；质量检查历史、模板旧版本唯一留痕=审计 detail（不建历史表）。

## 本次经验沉淀

1. **"商用硬伤修复"类需求必须同时交付恢复路径，否则拦截即死锁**：本 Case 若只做到期拦截而不给 platform_admin 延期/转正接口，到期租户将永久锁死（平台现状无任何 edition/expire_time 修改入口）。今后凡新增"拦截/限制"类功能，PRD 必须包含"解除限制的最短路径"功能点或显式声明兜底手段（SQL/后台）。
2. **跨资产打通类需求要把"判定逻辑零侵入"写成显式 AC**：标准-门禁打通最易镀金成改门禁引擎；本次将"打通"压到展示级（双向可见+打回原因附引用），并用 AC-F1.7 Then"门禁判定行为不变（既有编排用例回归）"锁死边界。今后凡"A 引用 B"类联动，都应区分"展示级打通"与"判定级打通"并二选一写死。
3. **时间边界类口径必须在 PRD 给出可构造的数值表**：剩余天数若只写"7/3/1 天提示"，QA 无法断言 7h 算几天、第 8 天是否提示。本次 §4.3.1 口径表（含 ceil 取整、≤7×24h 窗口、now≥expire_time 时刻精确、四租户构造示例）直接可翻成用例——建议沉淀为 PRD 模板的"口径表"必备段（凡涉时间/阈值/等级边界即触发）。
