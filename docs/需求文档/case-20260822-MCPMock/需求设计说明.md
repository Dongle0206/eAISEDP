# PRD — MCP Mock 演示层（MockMcpProvider）

> Case: case-20260822-MCPMock
> 档位：fast（精简结构：背景 / 功能点 / AC / 范围外 / 开放问题）
> 状态：待评审
> 上游关联：PRG-005（企业资产适配 Jira/Confluence/GitLab）的前置演示层 case
> 日期：2026-09-07

## 1. 背景与目标

eAISEDP 的 MCP 适配层骨架已就绪：eaiselp-adapter 提供 MCPAdapter SPI（registerTool / invokeTool / listTools）、HttpMCPAdapter（真实 JSON-RPC）与 StubMCPAdapter，配置 `eaiselp.adapter.mcp.enabled` 默认 false；runtime 侧有 MCPController 与前端 mcp.html。PRG-005 要求真实对接 Jira / Confluence / GitLab，但外部系统当前不可得，"编排调外部工具"无法端到端演示与联调。

本 case 内置 **MockMcpProvider**：预置三源常用工具集的本地内存模拟实现。目标：

1. **端到端可演示**：管理页选工具 → 填参 → 调用 → 看结果，全链路走真实 MCP 通道语义；
2. **契约先行**：以 Mock 作为 HttpMCPAdapter 的本地回环测试靶，固化 JSON-RPC 2.0 请求/响应契约测试，真实 server 上线时**零代码改动**替换；
3. 为 PRG-005 解耦外部依赖，提前暴露工具 schema 设计问题。

约束：复用既有 mcp 权限（adapter:view / invoke，invoke 30/min 限流已有）；无新表、无 DDL；数据为内存态。工具集为**固定预置逻辑**（非可配置规则引擎），仅启用开关 / target endpoint 走配置。

用户故事（精简）：
- 作为平台演示者，我希望在无外部系统时通过管理页调用 Jira/Confluence/GitLab 形态的工具，以便演示与验证 MCP 适配链路；
- 作为 PRG-005 开发者，我希望有固化的 JSON-RPC 契约测试，以便真实 server 接入时零改动替换。

## 2. 功能点清单

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F1 | Mock 三源工具集（MockMcpProvider） | P0 | 实现既有 MCPAdapter SPI，注册 9 个工具：Jira create_issue / list_issues / get_issue；Confluence create_page / get_page / search_pages；GitLab create_mr / list_mrs / create_issue。内存存储，数据按 tenant_id 分桶隔离；所有工具响应携带统一 mock 标识。装配走既有配置体系（开关与切换方式见 Q1），不新增表、无 DDL |
| F2 | 管理页工具目录与试调用（mcp.html） | P0 | 工具目录按源（Jira / Confluence / GitLab）分组卡片展示（名称 / 描述 / 参数 schema）；选中工具按 schema 动态渲染入参表单；提交走 invokeTool；结果以转义 JSON 展示。复用 adapter:view / invoke 权限与 30/min 限流，不新增权限点 |
| F3 | JSON-RPC 契约固化（回环测试） | P0 | Mock 提供本地回环 endpoint 作为 HttpMCPAdapter 的 target，契约测试覆盖 initialize / tools/list / tools/call 的 JSON-RPC 2.0 请求与响应结构；测试 target 由配置注入，切换到真实 server 仅改配置不改代码 |

## 3. 验收标准（Given-When-Then）

### AC-01 工具注册与元数据完整（F1）
- **Given** Mock provider 已启用
- **When** 调用 listTools
- **Then** 返回恰好 9 个工具（jira.create_issue / jira.list_issues / jira.get_issue / confluence.create_page / confluence.get_page / confluence.search_pages / gitlab.create_mr / gitlab.list_mrs / gitlab.create_issue），每个工具含 name、description 与参数 schema（字段名 / 类型 / 必填标记）

### AC-02 Jira 工具链路（F1）
- **Given** 租户 T1 内无 Jira 数据
- **When** 依次 invokeTool：jira.create_issue(summary="X") → jira.get_issue(id) → jira.list_issues()
- **Then** create 返回带唯一 id 的 issue 对象；get_issue 按 id 返回该对象且字段一致；list_issues 至少包含该条

### AC-03 Confluence 工具链路（F1）
- **Given** 租户 T1 内已执行 confluence.create_page(title="发布手册", content=…)
- **When** 分别 invokeTool：confluence.get_page(id)、confluence.search_pages(keyword="发布")
- **Then** get_page 按 id 返回该页面；search_pages 按 title/content 关键字命中该页；用不存在关键字（如 "zzz_no_hit"）搜索返回空列表而非报错

### AC-04 GitLab 工具链路（F1）
- **Given** 租户 T1 内无 MR 数据
- **When** 依次 invokeTool：gitlab.create_mr(title, source_branch, target_branch) → gitlab.list_mrs()
- **Then** create 返回带唯一 id 的 mr 对象（含 source/target 分支字段）；list_mrs 包含该条；gitlab.create_issue 与 AC-02 同语义（同租户内 create 后可 get / list）

### AC-05 租户隔离（F1）
- **Given** 租户 T1 与 T2 各自创建 1 条 issue / page / mr
- **When** 以 T2 身份调用 list_issues / search_pages / list_mrs，并以 T1 数据的 id 调用 get_issue / get_page
- **Then** 列表类仅见 T2 自己的数据；T1 的 id 对 T2 返回"未找到"类结果，响应中不含 T1 数据的任何字段

### AC-06 mock 标识与存储边界（F1）
- **Given** Mock provider 处于启用状态
- **When** 任一 mock 工具被成功调用
- **Then** 响应体携带统一 mock 标识字段（字段规范见 Q2），且管理页展示结果中可见该标识
- 附加断言：本 case 不新增任何数据库表 / DDL / 迁移脚本；应用重启后所有 mock 数据清空（list 类工具返回空列表）

### AC-07 参数校验与错误结构（F1）
- **When** 以缺失必填参数调用任一工具（如 jira.create_issue 不带 summary），或调用不存在的工具名
- **Then** 均返回结构化错误（含可判读的 code 与 message），不抛 HTTP 500、不返回半成品成功对象

### AC-08 管理页目录与查看权限（F2）
- **Given** 用户 U1 具有 adapter:view 权限
- **When** 打开 mcp.html
- **Then** 按源分组展示 9 个工具卡片（名称 / 描述 / 参数摘要）；无 adapter:view 权限的用户不可见入口或接口返回 403

### AC-09 试调用表单、结果转义与限流（F2）
- **Given** 用户具有 invoke 权限并选中任一工具
- **When** 在按 schema 动态渲染的表单中填写参数并提交
- **Then** 结果以**转义后**的 JSON 文本展示（按纯文本渲染，参数或返回值中注入 `<script>` 类内容不执行）；同一用户 invoke 超过 30/min 被限流拒绝（复用既有限流，错误可判读）

### AC-10 JSON-RPC 2.0 契约（回环）（F3）
- **Given** Mock 以本地回环 endpoint 作为 HttpMCPAdapter 的 target
- **When** 适配层发起 initialize / tools/list / tools/call
- **Then** 每个响应符合 JSON-RPC 2.0：`jsonrpc:"2.0"`、id 与请求一致、result 与 error 二选一；上述断言固化为自动化契约测试并纳入现有测试集（现有 629 项测试不回退）

### AC-11 配置化 target 零改动替换（F3）
- **Given** AC-10 契约测试全绿
- **When** 仅修改配置，将 adapter target 从 mock endpoint 切换为另一符合同契约的 endpoint（如第二测试实例）
- **Then** 适配层代码无任何改动，同一契约测试套件仍全部通过（证明真实 server 上线时零代码改动替换）

> 非功能并入说明（fast 档不设独立章节）：安全（结果转义 / 权限 / 限流）见 AC-08 / AC-09；多租户数据隔离见 AC-05；存储边界（无 DDL / 内存态）见 AC-06；兼容（既有 629 测试不回退）见 AC-10。

## 4. 范围外

- 真实 Jira / Confluence / GitLab API 对接、认证（OAuth / Token）与网络层——属 PRG-005
- mock 数据持久化（数据库 / 文件）；重启后数据不保留为设计内行为
- 编排 / Agent 运行时自动调用 mock 工具（本 case 仅管理面手动试调用）
- 新增权限点、新表 / DDL、mock 数据管理界面
- 三源工具集扩展（超出预置 9 个工具）与可配置工具注册

## 本次经验沉淀

1. Mock / 演示层需求最易漏的 AC 是**租户隔离**（尤其"跨租户按 id 直取须返回未找到"）——"反正是假数据"的心态常导致多租户泄露在演示层被放过，本 case 将其列为独立 AC 并要求响应不含他租户任何字段。
2. "零改动替换"类目标不可写成愿景式表述，必须转译为可测断言：同一契约测试套件对配置化 target 均通过、切换仅改配置不改代码（见 AC-11 写法）。
3. fast 档 PRD 取消独立非功能章节时，须把安全项（转义 / 权限 / 限流 / 无 DDL）逐一并入 AC 并加"非功能并入说明"索引，否则精简档最容易丢失的就是安全与隔离验收口径。
