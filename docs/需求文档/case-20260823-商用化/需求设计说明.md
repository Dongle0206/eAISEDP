## 1. 背景与目标

### 1.1 业务背景

**（A）商业化只剩"半条闭环"。** case-20260820 F3 已交付：租户有 edition（trial/starter/pro/enterprise）+ expire_time，到期拦截（登录 40003/临期三档/派生三入口）+ U1 订阅查询 + U2 恢复端点 + t_quota 月度配额 + t_derivation 逐笔 token/cost 记录。但商业化运营仍靠"人工改库 + 线下 Excel"：

- **套餐不存在**：edition 是四值枚举而非商品——月价多少、含多少配额、开哪些层、可用哪些模型档位、超量怎么收钱，全在运营脑子里；给新租户开 starter 要 DBA 手工 UPDATE t_tenant + t_quota 多张表。
- **用量不可出账**：t_derivation 逐笔记了 token/cost，但月底"每个租户该收多少钱"没有账单——试用转正的租户一直在免费跑（到期拦截只拦 trial，付费版永不过期也不计费）。
- **升级无路径**：试用 → 付费、starter → pro 的变更没有标准操作（U2 是裸 edition/expire 字段修改，无套餐语义、无配额模板联动、无变更历史）。
- **SLA 无承诺**：对外报价时"什么档位对应什么响应/可用性承诺"无平台承载，服务出了问题也没有事故台账。

**（B）PRJ-006 是章程最后一个子项目。** 交付本 Case 后，PRG-001 从 dogfooding 三层治理到商用收费全链路闭口：租户生命周期完整（试用→转正→续费→升降级）、平台有收入口径（账单）、客户有服务承诺（SLA 展示 + 事故登记）。

### 1.2 业务目标与成功指标

| 目标 | 衡量指标 | 验收口径 |
|---|---|---|
| 套餐可定义 | 套餐 CRUD（code/月价/功能开关 JSON/SLA 档/超量单价/状态） | AC-F1.1~F1.4 |
| 升级有路径 | 选套餐一次性应用（edition+expire+配额+层开关+档位范围）+ 审计 | AC-F1.5/F1.6/F1.8 |
| 用量可出账 | 月度账单自动生成：月价+token 超量，口径精确（快照/边界/粒度/舍入） | AC-F2.1~F2.7 |
| 收款有单据 | 账单三态流转 draft→issued→paid + 平台账单列表 | AC-F2.8 |
| 客户看得见账 | 租户费用中心（本期用量/历史账单/超量明细） | AC-F2.9 |
| SLA 有承诺 | 套餐 SLA 三档展示 + 事故登记台账 | AC-F3.1~F3.5 |
| 权限与隔离 | 9 权限原子矩阵 + 租户数据隔离 + V8 幂等 | AC-G1/G2/G3、AC-F1.9/F2.10/F3.5 |

### 1.3 与项目群路线的关系

| 子项目 | 范围 | 关系 |
|---|---|---|
| PRJ-006 商用化 | **本 Case 承载全部**：订阅计划 + 计量账单 + SLA 轻量 | 交付后 PRG-001 章程闭口 |
| case-20260820 F3 | 试用到期拦截 + U1/U2 + t_quota + t_derivation | 本 Case 在其上生长：U2 扩展为套餐应用（向后兼容，AC-F1.8）；t_derivation 成为账单用量数据源 |
| 演进预留（PRJ-006+） | 支付网关/发票税务/多币种/自动可用率 | 见 §7 范围外与 §8 开放问题 |

### 1.4 层级归属结论（强制）

套餐管理/账单/费用中心/事故登记均为**平台运营或租户运营域能力，不限层**：任何层开关组合（strategy_enabled/program_project_enabled 全关的场景 C）下，付费租户的计费与事故管理功能完整可用（AC-G3）。新 API 不注册进 LayerGuardInterceptor。

## 2. 用户故事（INVEST 原则）

### US-1 平台运营（platform_admin）——套餐商品化
- 作为「平台运营」，我希望「定义和维护订阅套餐（编码/名称/月价/token 月配额与超量单价/功能开关（用户数上限、层开关覆写、模型档位范围）/SLA 档位/上下架状态）」，以便「商品目录化管理——报价、配额、服务承诺一处定义，不再每次人工改库」。

### US-2 平台运营——试用转正/升降级有标准路径
- 作为「平台运营」，我希望「在租户列表选择套餐一键应用：edition、expire_time、配额模板、层开关、模型档位范围一次性生效，且全程审计留痕」，以便「试用转正与升降级是一个可追溯的标准操作，而不是多表手工 UPDATE」。

### US-3 平台运营——月度出账与收款
- 作为「平台运营」，我希望「系统每月自动汇总出账（月费 + token 超量费，试用期不出账），我按 draft→issued→paid 人工标记已出账/已收款」，以便「每个付费租户每月该收多少钱有单可依，收款对账不再拍脑袋」。

### US-4 租户管理员（tenant_admin）——费用透明
- 作为「租户管理员」，我希望「打开费用中心看到本期用量与配额水位（token/case/派生/存储）、历史账单与超量明细、当前套餐的 SLA 承诺」，以便「用量透明、预算可控，知道钱花在哪、为什么超」。

### US-5 租户管理员/项目经理（tenant_admin + project_manager）——事故登记
- 作为「租户管理员/项目经理」，我希望「登记服务事故（发生时间/影响/恢复时间/根因）并维护恢复信息」，以便「服务质量有据可查，SLA 承诺兑现与否有台账支撑」。

### US-6 高管（executive）——服务承诺知情
- 作为「高管」，我希望「只读查看本租户的 SLA 承诺与事故列表」，以便「对平台服务质量与历史事故有总览」。

### US-7 工程师（engineer）——只读知情
- 作为「工程师」，我希望「只读查看事故列表」，以便「知道发生过哪些服务问题，知识传播」。

**INVEST 自检**：各故事独立可验收（对应 §5 AC）；可协商（页面形态、表名、生成时机可由 UX/SE 调整——**计费口径 B1~B6 与权限矩阵不可**）；对七类角色各有价值；规模适合单 story；可测（AC 全 Given-When-Then 且含构造数值）；时间盒在本 Case 内。

## 4. 功能需求详述

### 4.1 F1.1 套餐定义管理

#### 4.1.1 数据契约（语义，SE 定稿表名，候选 t_subscription_plan）

平台级全局表（tenant_id=0，进 IGNORE_TABLES，同 t_permission 先例）：

| 字段 | 语义 |
|---|---|
| code | 枚举 starter/pro/enterprise/custom（领域字典，应用层校验非法 400）；**标准三档（starter/pro/enterprise）同 code 的在架套餐至多一份（应用层校验，重复创建 400）；custom 可多份**（逐租户定制，以名称区分） |
| name | 套餐名，全局唯一（uk，同 V4/V6/V7 uk(tenant,name) 惯例的平台级变体） |
| monthly_price | 月价（元，DECIMAL(14,2)，≥0，=0 合法——免费定制档；单位元对齐 V7 金额裁决先例） |
| token_overage_price | token 超量单价（元/千 token，DECIMAL(12,6)，≥0；精度 6 位小数支撑低单价） |
| features | 功能开关 JSON：{max_users, max_cases, token_limit, case_limit, derivation_limit, storage_limit_mb, layer_overrides:{strategy_enabled, program_project_enabled}, model_tiers:[...]}；服务端结构校验（必需键与值域），未知键忽略（向前兼容） |
| sla_level | 枚举 bronze/silver/gold（必填，见 §4.7） |
| status | active/disabled（上下架；disabled 不可被应用，存量绑定租户不受影响——继续按已生效订阅运行与出账） |
| 常规审计列 | create_time/update_time/create_by/update_by/is_deleted（平台级惯例；仅逻辑删，不物理删——账单套餐快照自洽不依赖套餐行存续） |

#### 4.1.2 V8 预置 seed 与存量回填

- V8 预置官方三档套餐 seed（starter/pro/enterprise，定价模板由运营在页面上改，seed 值仅占位满足"同名默认档存在"）。
- 存量 edition∈{starter,pro,enterprise} 的租户，V8 幂等回填绑定同名默认套餐（口径：绑定关系空且 edition 命中标准档时绑定；trial/未知 edition 不绑）。trial 租户不绑套餐（沿用既有拦截语义，AC-F1.8 回归）。

### 4.2 F1.2 套餐应用（U2 扩展 = 订阅变更标准路径）

#### 4.2.1 行为契约

- 入口：U2 扩展入参 `planCode`（或 planId）；**一次事务**完成：
  1. t_tenant.edition = 套餐 code（custom 套餐 → edition 取该套餐 `edition_override` 或 fixed=custom 的映射语义由 SE 定，PRD 只约束"custom 套餐应用后租户 edition 非 trial 且出账正常"）；
  2. t_tenant.expire_time：付费档到期拦截不生效（既有语义：非 trial 忽略 expire），应用时缺省置空（Q4 可裁"置 +1 年"）；
  3. t_quota 当前期行按套餐配额模板覆写（token/case/derivation/storage limit + monthly_cost=套餐月价）；
  4. t_tenant 层开关按 layer_overrides 覆写（覆写语义：套餐说开就开、说关就关——商品边界清晰，AC-F1.5 断言）；
  5. 模型档位范围写入租户上下文（派生三入口校验，见 §4.2.2）。
- 任一步失败全部回滚（AC-F2 断言无半应用状态）。
- **变更历史审计**：复用/扩展现有 `tenant_edition_change` 审计事件，detail 含 old→new 的 edition/expire_time/配额四限/层开关/档位范围快照与操作者（数据源同时是 B3 转正判定依据；是否独立 t_subscription_change 表由 SE 裁决，Q1）。
- **向后兼容**：不传 planCode 时 U2 保持既有单字段 edition/expire 语义不变（存量测试与脚本零影响，AC-F1.8）。

#### 4.2.2 模型档位范围 enforcement

### 4.4 F2.1 月度账单生成（计费口径唯一权威）

#### 4.4.1 计费口径 B1~B6（冻结；QA 照此构造，Q4 裁决可整体替换）

| # | 口径 | 定义与构造 |
|---|---|---|
| **B1 月末快照** | 月费、token 超量单价、token 配额基准，一律取**账期结束时刻（次月 1 日 00:00，Asia/Shanghai）租户生效套餐**的值——与出账时点同源，单一快照贯穿，无期初/期中拆分 | 账期内升降级 → 本期按**期末档**计价（例：8-15 starter→pro，8 月账单按 pro 月价） |
| **B2 试用期不出账** | 出账时点租户 edition=trial（全程试用）→ 本账期**不生成账单记录**（t_invoice 无行，而非 0 元账单） | 整月 trial → 无账单 |
| **B3 转正赠送** | 账期开始时刻（当月 1 日 00:00）为 trial、期内转付费 → 本期**不出账**（转正当月赠送），下期起按 B1 正常出账。期初状态依据 = F1.2 变更审计（或订阅历史表，Q1） | trial→pro @8-15 → 8 月无账单，9 月 1 日出 9 月账单（若有用量） |
| **B4 整月计费** | 不按天折算（含月中新建即付费租户、月中档间升降级；按天折算属 §7-6） | 8-20 新建绑定 pro → 8 月出整月月价 |
| **B5 超量计算** | 超额 token = max(0, Σ本期成功派生 token − 本期 token 配额基准)；**计费单位 = 千 token，向上取整 ceil**（不足 1 千按 1 千，仅对超额部分）；超量费 = ceil 单位数 × 套餐 token_overage_price。用量源 = t_derivation 逐笔聚合（input_tokens+output_tokens，成功终态记录计、失败/运行中不计——成功态枚举值以 V1 schema 为准，SE/QA 对齐）；账期归属时间戳 = started_at（缺失 fallback create_time）；t_quota.token_used 仅作实时水位展示，不作账单口径 | 构造例：pro 月价 999.00、配额 5,000,000、单价 8.00 元/千 token；本期成功用量 6,001,500 → 超额 1,001,500 → ceil=1002 千 → 超量费 8,016.00 → **应缴 9,015.00** |
| **B6 金额舍入** | 中间计算 BigDecimal 全精度不舍入，**仅最终应缴金额 HALF_UP 保留 2 位小数（元）**；存储 DECIMAL(14,2) | 构造例：custom 月价 99.99、单价 0.335 元/千 token、超额 3,000 token → 3 千 × 0.335 = 1.005 → 100.995 → **101.00**（进位） |

**账期与幂等**：账期 = 自然月 `[当月 1 日 00:00:00, 次月 1 日 00:00:00)`，时区 Asia/Shanghai，period 键 `yyyy-MM`（与 t_quota.period 同构）；t_invoice **uk(tenant_id, period)** 防并发/重复生成；重跑口径——已存在 draft 账单 → 重算覆盖（用量此后仍可能补记）；已 issued/paid → **不覆盖**（WARN 日志），如需修正人工作废重开属范围外（§7-1）。

**触发时机**（Q2，缺省建议）：每月 1 日 02:00 定时全量生成 + platform_admin 手动补生成入口（同幂等口径）；AC 不绑定触发方式（QA 直接调生成逻辑断言结果，触发方式用例随 Q2 裁决补）。

#### 4.4.2 数据契约（候选 t_invoice，租户级）

period（账期键）/tenant_id/plan_id + 套餐快照（code/名称/月价/超量单价/SLA 档，**快照自洽，套餐后续改价不影响已生成账单**）/用量明细 JSON {tokenUsed, tokenLimit, tokenOverageTokens, ktokenBilled, derivationCount, caseCount, storageUsedMb}/monthly_price（快照）/overage_fee DECIMAL(14,2)/amount_due DECIMAL(14,2)（=月价+超量费，服务端算）/status（draft/issued/paid）/issued_time/paid_time/常规审计列。**平台内部成本（t_derivation.cost）不进账单任何字段与 API**（信息隔离，§6-3）。

### 4.5 F2.2 账单状态流转与平台账单列表

### 4.6 F2.3 租户费用中心（cost-center.html，tenant_admin）

### 5.2 F2 计量与账单（10 条）

**AC-F2.1 试用期不出账 + 转正赠送**
- **Given** 租户 A 全月 trial 且有派生用量；租户 B 8 月 1 日为 trial、8-15 转 pro、8 月有用量
- **When** 9 月 1 日触发 8 月账期出账
- **Then** A 与 B 的 8 月账期均**无 t_invoice 行**（不是 0 元账单）；B 自 9 月账期起正常出账

**AC-F2.2 标准出账数值断言（B1/B4/B5）**
- **Given** 租户 C 绑定 pro（月价 999.00、token 配额 5,000,000、超量单价 8.00 元/千 token），8 月成功派生合计 6,001,500 token（含 input+output，失败记录 10,000 token 不计入）
- **When** 生成 8 月账单
- **Then** 应缴 amount_due = **9,015.00**（999.00 + ceil(1,001,500/1000)=1002 千 × 8.00 = 8,016.00）；明细 JSON 含 tokenUsed/tokenLimit/超量 token/ktokenBilled=1002 及套餐快照五字段；构造月中 8-20 新建即付费租户 → 同样出整月月价（B4）

**AC-F2.3 千 token ceil 边界**
- **Given** 两个租户超额 token 分别恰为 1,000,000 与 1,000,001（其余条件同 AC-F2.2）
- **When** 出账
- **Then** 计费单位数分别为 1000 与 1001（1000 恰不进位、1001 进一位）；超额 1 token 亦计 1 千（ceil 下界）

**AC-F2.4 未超量不出超量费**
- **Given** 月用量 4,999,999 token（≤ 配额 5,000,000）
- **When** 出账
- **Then** 超量费 0.00、ktokenBilled=0，应缴 = 月价 999.00

**AC-F2.5 金额 HALF_UP 舍入**
- **Given** custom 套餐月价 99.99、超量单价 0.335 元/千 token、本期超额 3,000 token
- **When** 出账
- **Then** 超量费 1.005 全精度参与相加 → 100.995 → **应缴 101.00**（HALF_UP 2 位进位断言；库存值 DECIMAL(14,2)）

**AC-F2.6 账期边界与归属时间戳**
- **Given** 两笔成功派生：started_at=2026-08-31 23:59:59 与 started_at=2026-09-01 00:00:00（各 100,000 token）；另有一笔 started_at 为 NULL、create_time=8-15 的成功记录
- **When** 分别生成 8 月/9 月账单
- **Then** 前笔计入 8 月、次笔计入 9 月（闭开区间 `[1日00:00, 次月1日00:00)`）；NULL fallback 笔按 create_time 计入 8 月；失败终态记录一律不计（B5）

**AC-F2.7 出账幂等重跑**
- **Given** 同一租户同一账期已存在账单，状态分别为 draft / issued / paid 三个副本场景
- **When** 重复触发生成
- **Then** draft → 重算覆盖（构造补记一笔用量后金额更新）；issued/paid → 不覆盖且 WARN 日志；uk(tenant_id, period) 保证无第二行

**AC-F2.8 账单状态机**
- **Given** platform_admin 与一张 draft 账单
- **When** 依次执行 draft→issued、issued→paid / 尝试 draft→paid 跳变 / issued→draft 回退 / paid 后再流转
- **Then** 合法顺次流转成功并各写审计（操作者/时间落 issued_time/paid_time）；三类非法流转均 400

**AC-F2.9 费用中心可见性与 draft 隔离**
- **Given** 租户 T（tenant_admin）有 8 月 issued、paid 账单各一张及 9 月 draft 一张，本期 t_quota 水位有值
- **When** 打开费用中心
- **Then** 四维用量水位、当前套餐卡片（含 SLA 承诺）、issued/paid 账单与超量明细可见；**9 月 draft 账单不可见**；账单金额与平台侧一致

**AC-F2.10 账单租户隔离与 RBAC**
- **Given** 租户 B 的 tenant_admin / engineer 身份，租户 A 存在账单
- **When** B 查询 A 的账单/费用中心数据 / B 调用平台账单列表或标记收款 API / engineer 打开费用中心
- **Then** 跨租户查询 404/空（拦截器隔离）；平台侧 API 403（1084/1085 仅 platform_admin）；费用中心 403（1086 仅 tenant_admin/platform_admin）

- **When** 使用费用中心、事故登记、账单查询
- **Then** 功能完整可用，无 43001/43002 业务码；新 API 未注册 LayerGuardInterceptor

## 6. 非功能需求

1. **性能**：费用中心/账单列表/事故列表 P95 < 500ms（V7 水位先例）；月度出账全量（≤200 租户 × 单租户月度成功派生 ≤5 万笔假设）< 60s，SUM 聚合走既有 t_derivation 索引评估由 SE 定；定时任务错峰每月 1 日 02:00（避开 0 点批处理窗口）。
2. **金额一致性**：全程 BigDecimal（禁 float/double），存储 DECIMAL；应缴金额服务端生成，客户端提交金额字段一律忽略（V7 防伪造先例）；uk(tenant_id, period) 防并发重复出账。
3. **信息隔离**：平台内部成本（t_derivation.cost）不出现在任何租户可见 API/页面/账单字段（客户不应看到平台内部成本）；draft 账单对租户不可见。
4. **多租户**：t_invoice/t_incident 租户级（拦截器自动过滤）；t_subscription_plan 平台级进 IGNORE_TABLES；platform_admin 跨租户通道沿 U1/U2/TenantController 既有先例。
5. **审计**：套餐创建/编辑/上下架、套餐应用、账单三态流转全审计（操作者/时间/detail old→new）。
6. **兼容性**：U2 向后兼容（AC-F1.8）；既有 656 测试零回归；前端沿用 jQuery 既有页面风格与组件，不引入新框架。
7. **时区与键**：账期口径 Asia/Shanghai；period 键 `yyyy-MM` 与 t_quota.period 同构。
8. **国际化/文案**：平台当前中文单语（无多语言清单要求，CLAUDE.md 未注入 i18n 约定）；枚举展示文案集中一处定义（V7 P6 先例）；多语言/多币种见 §7。
9. **安全**：金额/单价/JSON 功能开关服务端校验（负值/非法结构 400）；套餐管理全部端点过权限链（非应用层角色判断）。

## 7. 范围外（显式不做，防镀金）

1. **支付网关/在线支付/自动扣款**——paid 为人工标记收款；
2. **发票与税务**——开票、税率、税额计算均不做，账单仅为收款依据单据；
3. **多币种与汇率**——人民币单币种（DECIMAL 元）；
4. **SLA 自动可用率计算与监控集成**——不做 actuator health 历史采样、不对接监控系统；
5. **SLA 违约赔付/服务积分**——承诺纯展示；
6. **按天折算/按量后付费**——整月月价 + token 超量是唯一计费模型（B4）；
7. **case/派生/存储超量计费**——账单明细展示用量，但仅 token 参与计费（Q3 演进）；
8. **欠费自动停服**——非自动，人工经 U2/订阅变更处理；
9. **租户自助购套餐/自助升降级下单**——订阅变更由 platform_admin 操作；
10. **账单 PDF 导出/邮件推送/作废重开**——本期列表页查看即可。

## 9. 本次经验沉淀

1. **计费类需求的口径必须"单点冻结"**：期初/期末/期中三种快照语义混用是账单争议根源——本 PRD 用"月末快照 + 转正赠送"两条规则覆盖全部场景（月中升降级/月中转正/月中新建），后续计费类需求应先画"订阅状态 × 时间轴"矩阵再定口径。
2. **既有端点扩展必须写"向后兼容 AC"**（AC-F1.8）：U2 扩展为套餐应用时，最容易漏的验收是"不传新参数时旧行为逐分支回归"，否则 656 存量测试的绿基线会被静默破坏。
3. **平台内部成本与客户计费价必须显式隔离并写成 AC 可断言的禁令**（§6-3）：t_derivation.cost 天然存在，若不在 PRD 层面禁止其进入租户可见面，实现时极易"顺手"带出造成商业敏感信息泄露。
