## 一、结论

**通过（附整改建议）。高危 0 项、中危 2 项、低危 6 项。**

两项中危均为**租户内横向权限粒度**问题（对象级归属校验缺失，与 V5 seed 权限描述存在偏差），不涉及跨租户越权、不涉及注入与数据外泄，有审计留痕兜底，不构成上线阻断项；建议随下一迭代补对象级校验或修订 seed 描述口径。注入、XSS、埋点伪造面、DORA 越权四个重点专项全部核验通过。

## 二、专项核验结果（任务书五项检查点）

### 2.1 越权检查 —— 通过（附 2 中危）

**① 28 新端点权限注解 vs V5 seed 1046~1058：逐一对齐，无遗漏、无降级。**

| Controller | 端点数 | 权限码（V5 seed id） |
|---|---|---|
| MilestoneController（/api/v1/milestones） | 6 | milestone:view/create/edit（1046~1048） |
| DependencyController（/api/v1/project-dependencies） | 7 | dependency:view/create/edit（1049~1051） |
| DoraMetricsController（/api/v1/metrics/dora） | 1 | dora:view（1052） |
| AdrController（/api/v1/adrs） | 6 | adr:view/create/edit（1053~1055） |
| TechRadarController（/api/v1/tech-radar） | 6 | radar:view/create/edit（1056~1058） |
| ProgramController `GET /{id}/milestone-timeline` | 1 | milestone:view（挂 programs 前缀，C6 收敛） |
| PrincipleController `GET /{id}/adrs` | 1 | principle:view（ADR 不限层，见低危 L6） |

拦截器链完整（`RuntimeWebMvcConfig`）：限流(0) → JWT 认证(1) → 权限(2) → 层开关(3)，全部覆盖 `/api/**`；28 端点无一漏注解、无一白名单直通。`PermissionInterceptor` 方法级注解优先，权限码经查库匹配，无绕过面。13 条权限原子 × 角色矩阵（platform_admin/tenant_admin 全量、project_manager 9 项、engineer 2 项 view、executive 5 项 view）与 seed 授权行 2092~2133 逐行核对一致。

**② 跨租户拦截器覆盖：通过。**
- 三新表 `t_project_dependency` / `t_adr` / `t_tech_radar_item` 均**不在** `EaiselpTenantHandler.IGNORE_TABLES`，MyBatis-Plus 租户拦截器自动注入 `tenant_id` 条件，五 Service 全部走标准 LambdaWrapper 查询，无裸 SQL。
- `t_governance_log` 在 IGNORE_TABLES：**写入**走 `AuditServiceImpl`，tenant_id 取 JWT claims（防伪造，G13）；**手写读取**两处（`AdrServiceImpl.loadDeprecateReasonFromAudit`、`DoraMetricsService.loadFirstDoneTransit`/excludedCount）均显式 `eq(tenant_id, TenantContext.get())` 且命中 V5 新增索引 `idx_tenant_action_time`，不跨 IGNORE 边界 JOIN。
- 横向越权根基核验：`X-Tenant-Id` 请求头虽被 `TenantContextFilter` 直接采信，但 `JwtAuthInterceptor` 解析 JWT 后 `LoginUser.set()` 以 `claims.tenantId` **覆盖** TenantContext（`LoginUser.java:15`），且 `t_user.tenant_id NOT NULL`（V1 baseline:35）保证 claims 恒有值、覆盖恒发生；网关纯路由不新增攻击面。**当前无利用面**，机制脆弱性记低危 L1。

**③ 里程碑两级归属越权：确认为中危 M2**（见下文）——跨租户安全（ownerId 经拦截器过滤后跨租户即 404），租户内可"挪窝"。

### 2.2 注入检查 —— 通过

- **复活语义自定义 SQL（绕过 @TableLogic 两条）**：`ProjectDependencyMapper.selectDeletedEdge / reviveEdge` 全部参数 `#{}` 预编译绑定（tenantId/fromProjectId/toProjectId/dependencyType/note/updateBy 六参数无一 `${}` 拼接），且 WHERE 显式钉死 `tenant_id = #{tenantId}`（与拦截器注入值同源，双保险）。**无 SQL 注入。**
- **环检测路径拼接输出**：Service 层 `pathDisplay` 输出纯数字 id 串；Controller 层 `enrichCyclePathWithNames` 批查项目名换名，解析失败原样降退不硬错。项目名（用户可控）拼入文案后，前端 `dependency-board.html:242/458` 均 `escapeHtml()` 后入 `.html()`；create 失败路径走 `alert()`（纯文本无 HTML 解析）。**无 XSS。**
- **ADR 五段 TEXT 存储回显**：`adr-list.html` 的 `escapeHtml/escapeAttr` 覆盖 `& < > " '` 五字符；五段正文（context/decision/consequences）经 `sec()` 统一转义；`title`、`data-code`、`data-name`、`data-status`、`title=` 悬浮属性全部过 `escapeAttr`；`deprecateReason`（审计回显字段）亦转义（adr-list.html:292）。radar/dependency/dora 三页同构实现逐行抽查一致。**存储型 XSS 防护完备。**

### 2.3 埋点链路 —— 通过（derivationId 无伪造面，确认）

`markGateResult`（OrchestrationService:171）的 `derivationId` 来源链：`DerivationPersistenceService.persist()` 落库成功后回填（同步路径=雪花 ID save 回填，异步路径=预占主键），**纯内部值、非用户输入**；落库失败时该行不可达、保持 null 跳过。`gateValue` 仅为硬编码字面量 `"PASS"/"FAIL"/"FAIL_WARN"`（`parseGateResult` 正则产物），无注入面。UPDATE 走 `LambdaUpdateWrapper eq(id)` + `runAsync` 线程显式 `TenantContext.set(tenantId)`（启动线程从 JWT 上下文取值传入，非请求参数）——租户拦截器生效，无跨租户写入。埋点全吞异常仅 ERROR 日志，符合"不影响编排主流程"铁律。

### 2.4 DORA 数据泄露 —— 通过

`resolveProjectPool`：scope=project/program 时 `selectById/selectList` 走租户拦截器（t_project/t_program 均为普通租户表），**跨租户 scopeId 直接 404，无指标泄露**。同租户内 project_manager/executive 可查任意项目/项目群指标——与 PRD §4.6 授权矩阵（dora:view 为租户级只读）一致，属设计授权而非越权。5min TTL 缓存 key 含 `tenantId` 前缀（`tenantId|scope|scopeId|days`），无跨租户缓存串号。LT 的"excludedCount 全历史审计补查"同样手写 tenant_id。

### 2.5 逻辑检查

- **ADR superseded 成环：静态不可能，并发存在低危竞态（L2）**。`AdrStatus` 状态机 deprecated/superseded 为终态无出边，且 supersededBy 目标须 accepted 且≠自身——链式指向不可能回环（链上前者均已终态）。唯一缺口：两个 transit 并发交错（互读对方 accepted 后双双提交）可造成互指，记低危。
- **依赖删除权限：中危 M1**（见下文）。
- **雷达审计完整性：满足 AC-F5.3 最低契约**（环移动记 fromRing→toRing），字段级明细不足记低危 L4。
- 环检测器防御上界（节点 10000/边 50000 抛 400）+ 显式栈 DFS 防栈溢出，资源耗尽防护到位；复活路径的环预检在 save 前统一执行，"删边期间闭合成环再复活"场景仍被拦截（核实无误）。

## 三、风险清单

### 中危（2）

**M1 依赖边编辑/删除缺对象级权限校验，与 V5 seed 描述不符**
- 位置：`DependencyController.update/delete` + `DependencyServiceImpl.edit/remove/reviveOrConflict`
- 现象：seed 1051 描述"含删除（**限依赖双方项目经理或 tenant_admin**）"，实现仅校验租户级 `dependency:edit`——任何 project_manager（无论是否为依赖双方）可改向备注、改类型、删除、乃至触发复活任意租户内依赖边。代码注释（C7）自认"细粒度不可判定，按 seed 口径"，但 seed 描述本身承诺了细粒度，属**权限声明与实现偏差**。
- 影响：租户内横向越权（L2 治理数据完整性）；有 dependency_update/delete 审计留痕（含 revived:true）可事后追溯。
- 建议：短期修订 seed 1051 描述为"dependency:edit 持有者"；中期在 `remove/edit` 前校验操作者为 from/to 项目 owner 或 tenant_admin。

**M2 里程碑编辑可改归属（ownerId 挪窝）+ 无对象级校验**
- 位置：`MilestoneController.update` + `MilestoneServiceImpl.edit`
- 现象：① PUT body 携带 `ownerType/ownerId` 直接覆盖归属——任意持 `milestone:edit` 者可把任意里程碑挪到同租户任意项目/项目群（挪窝后原项目时间线失真，programTimeline 聚合随之污染）；② 任意 project_manager 可 create/edit/transit/delete 租户内**任何**项目的里程碑（含他项目），无"操作者与归属项目关系"校验。任务书点名的"改 ownerId 操作他项目里程碑？"成立。
- 影响：租户内横向越权 + 治理数据完整性；milestone_update/transit 审计留痕但 detail 不记录归属变更前后值，事后追溯弱。
- 建议：edit 不接受 ownerType/ownerId 变更（归属变更走独立端点或删除重建）；审计 detail 补 ownerType/ownerId 前后值；同 M1 一并评估对象级校验。

### 低危（6）

**L1 租户上下文机制脆弱（X-Tenant-Id 头深度防御不足）**
`TenantContextFilter` 直接采信请求头，安全性完全依赖 `LoginUser.set()` 的事后覆盖顺序与 `t_user.tenant_id NOT NULL` 约束；网关不剥离外部 `X-Tenant-Id`。当前无可利用路径（claims.tenantId 恒非空必覆盖），但任何未来改动（白名单端点、异步消费、claims 可空化）都会立即打开跨租户伪造面。建议：网关 `RemoveRequestHeader=X-Tenant-Id` 或删除该 Filter（注释已声明前端不传）。

**L2 ADR superseded 并发互指竞态**
两 transit 并发交错（均读到对方 accepted）可造成 A↔B 互指，破坏"链式不可回环"语义。建议 UPDATE 加条件守卫（`set status where status='accepted'`）或 transit 加分布式锁。

**L3 ADR/雷达逻辑删行占唯一键，删后不可重建（且 ADR 编号无长度校验）**
`uk_adr_tenant_code` / `uk_radar_tenant_name` 不含删除位且无依赖表的复活语义——逻辑删后同编号/同名重建 400（依赖表有 C2 复活，ADR/雷达没有，行为不一致）；另 `AdrSaveRequest.adrCode` 无长度校验，超长触发 DB 异常 500 而非 400。建议补复活语义或编号续推 + `adrCode ≤64` 校验。

**L4 雷达审计完整性偏弱**
`radar_update` 仅在 ring 变化时记 `fromRing/toRing`，quadrant/reason/reviewedAt 变更无字段级前后值（对比 milestone 的 verb/from/to 结构）。满足 AC-F5.3 最低契约，但"审计即历史"的兜底强度低于同批功能。建议 detail 补全字段级 diff。

**L5 前端枚举值直插的防御深度缺口**
`adr-list.html:257/282` 的 `(STATUS_TEXT[st] || st)`、`dora-board.html` 的 `bandBadge(band)`——枚举外的值会未转义直插 HTML。当前后端状态机/分档函数保证值域受控，仅 DB 脏数据可触发。建议统一 `escapeHtml(STATUS_TEXT[st] || st)`。

**L6 原则关联 ADR 端点权限口径不一致**
`GET /api/v1/principles/{id}/adrs` 用 `principle:view` 而非 `adr:view`——两权限码持有集合不同（engineer 有 adr:view 无 principle:view），该入口实际泄露/收敛范围与 ADR 主入口不对齐。只读、同租户，影响轻微。建议统一为 `adr:view` 或双码任一。
