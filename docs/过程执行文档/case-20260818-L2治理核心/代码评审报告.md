### 2.3 环检测 DFS + 复活语义 ✔

- `DependencyCycleDetector.wouldCycle`：显式栈 DFS 从 to 找 from，parent 链还原 `[from, to, ..., from]` 闭环路径；每节点至多入栈一次（parent.containsKey 防重），正确性成立；自依赖兜底 `[x,x]`。
- `findCycles`：最小节点出发 + 只走 >start 节点的经典规范化，每个简单环恰好发现一次，LinkedHashSet 去重；自环报 `[x,x]`。
- 防御：节点>10000/边>50000 抛 GraphSizeExceededException→上层翻译 400；深度>max(1000,V) 记 ERROR 截断（迭代实现无栈溢出风险，注释已论证）。
- **400 确认**（C5）：`precheckCycle` → `BizException(400, "依赖成环，禁止登记：路径")` + WARN 含路径（§6.6 观测点）；HTTP 200+业务码 400 符合 R 统一契约。Controller 层 `enrichCyclePathWithNames` 把 id 换项目名，解析失败原样返回不硬错。AC-F3.3 两节点/三节点用例在 DependencyCycleDetectorTest（16 用例）覆盖。
- relates_to 不进图 ✔（strongEdges 只查 depends_on；blocked 判定同样跳过）。
- **注入面：零**。`ProjectDependencyMapper` 两条自定义 SQL 全部 `#{}` 参数预编译绑定，无 `${}` 拼接；tenant_id 显式等值（与拦截器注入同源冗余一致）；`selectDeletedEdge` 绕过 @TableLogic 是复活语义唯一载体，`ORDER BY id DESC LIMIT 1` 防脏数据多行；`reviveEdge` 带 `is_deleted=1` 条件防并发双复活。测试含"登记→删除→重登"复活用例。

### 2.5 ADR superseded 链成环可能：**结构性不可能** ✔

A sup B 后 A=superseded（终态无出边）；superseded_by 指向校验要求目标 status=accepted 且≠自身（`AdrServiceImpl.transit` L156-163）。链上每条边从 superseded 态指向 accepted 态，而 accepted↛superseded 不可逆（终态），故 A sup B sup A、A sup B sup C sup A 均被"目标须 accepted"前置拒绝——**链方向由状态单调性保证无环**。编辑接口不可改 supersededBy（只走 transit）堵住旁路。终态回退 400 ✔（isTerminal 专属文案）。
