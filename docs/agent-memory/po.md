# PO 角色经验库

> 编排者派生前读本文件按分层策略注入，角色产出后编排者归档于此。

### [2026-08-18] 数据模型草案与验收标准必须交叉核对
`tags: 数据模型, 验收标准, 交叉核对, severity: high`
- 现象：开发侧已有 V4 迁移草案时直接按草案写 AC，发现草案缺"项目-原则绑定载体"和"租户分层开关存储位"两处
- 根因：草案由技术视角产出，未从验收视角反向检查每条 AC 是否有数据承载
- 解法：PRD 产出时逐条 AC 问"这个行为的数据落在哪张表哪个字段"，落不下的列为开放问题
- 关联文件：V4__three_tier_model.sql / 需求设计说明.md

### [2026-08-18] 架构原则类需求须翻译为否定性验收标准
`tags: 架构原则, 验收标准, severity: mid`
- 现象：原则（如"每层可独立启用"）直接写进 AC 无法测试
- 根因：原则是约束声明，验收需要可观察行为
- 解法：每条原则配"Given 违反原则的状态 When 执行相关操作 Then 被拒绝/降级/无副作用"的否定性 AC
- 关联文件：需求设计说明.md §4

### [2026-08-18] 不可见机制必须定义生效证据载体
`tags: 上下文注入, 可观测性, severity: high`
- 现象：下行注入（原则注入编排上下文）是内部机制，用户不可见，无法验收"是否真的注入了"
- 根因：机制生效与效果可证是两回事
- 解法：不可见机制必须定义三处留痕（持久化字段+日志摘要+编排详情可查），留痕本身升格为 P0 子需求
- 关联文件：需求设计说明.md AC-F7.1
