# 双机协同开发流程（本机开发 + 新机部署）

> **本机（Dev 机）**：写代码、跑 dogfooding（ZCode）、push GitHub
> **新机（Deploy 机）**：跑 Docker、跑后端服务、暴露 API
> **本机浏览器**：访问新机 API + 调试前端

---

## 二、日常开发闭环（10 步循环）

### 场景：你在本机改了后端代码，想验证

```
┌─── 本机 ──────────────────────────────────────────────┐
│ 1. 在本机 ZCode/VSCode 改代码（e.g. 加一个 API）       │
│ 2. 本机编译验证（mvn compile，看是否有错）            │
│ 3. git add + git commit                               │
│ 4. git push origin main                               │
└──────────────────────┬────────────────────────────────┘
                       │
                       ▼
                ┌──────────────┐
                │   GitHub     │
                └──────┬───────┘
                       │
┌─── 新机 ──────────────┴───────────────────────────────┐
│ 5. 在新机 cmd 跑:                                      │
│    cd D:\eaiselp\platform                              │
│    service.bat deploy                                  │
│    （自动：pull + build + up + 等 30 秒）              │
│ 6. 检查容器状态: service.bat status                    │
│ 7. 启动 runtime: service.bat runtime                   │
└──────────────────────┬────────────────────────────────┘
                       │
                       ▼
┌─── 本机 ──────────────────────────────────────────────┐
│ 8. 浏览器/Postman 访问:                                │
│    http://192.168.1.B:8080/api/<新接口>                │
│ 9. 看响应是否符合预期                                  │
│ 10. 如果不对 → 回到第 1 步改代码                       │
└───────────────────────────────────────────────────────┘
```

**一次循环耗时**：3-5 分钟（其中 mvn package 占大头）。

## 三、各场景操作清单

### 场景 A：改了 Java 后端代码

**本机**：
```cmd
cd D:\AI\mywork\platform
mvn clean compile -DskipTests      REM 本机先验证编译
git add .
git commit -m "feat: 加 XXX 功能"
git push origin main
```

**新机**（远程桌面/SSH 过去）：
```cmd
cd D:\eaiselp\platform
service.bat deploy
```

`deploy` 一键完成：pull → build → up → 等待 → 显示状态。

### 场景 B：改了 SQL schema

**本机**：改 `eaiselp-data/src/main/resources/db/schema.sql`，commit + push。

**新机**：
```cmd
REM schema.sql 在 docker-entrypoint-initdb.d，只在第一次创建 DB 时执行
REM 如果 DB 已存在，需要手动执行：
docker exec -i eaiselp-mysql mysql -uroot -proot eaiselp < D:\eaiselp\platform\eaiselp-data\src\main\resources\db\schema.sql

REM 或者删掉 DB 重建（开发期方便）：
REM docker exec eaiselp-mysql mysql -uroot -proot -e "DROP DATABASE eaiselp; CREATE DATABASE eaiselp;"
REM docker exec -i eaiselp-mysql mysql -uroot -proot eaiselp < D:\eaiselp\platform\eaiselp-data\src\main\resources\db\schema.sql
```

### 场景 C：改了 application.yml 配置

**本机**：改 yml，commit + push。

**新机**：重新启动 runtime（不需要重启 MySQL/Nacos）：
```cmd
cd D:\eaiselp\platform
git pull
REM 如果改的是 pom.xml 才需要 rebuild：
REM mvn clean package -DskipTests
REM 否则直接重启 runtime：
taskkill /fi "windowtitle eq eaiselp-runtime*" /f
service.bat runtime
```

### 场景 D：本机前端调用新机后端

**前端配置**：
- 前端默认调 `http://localhost:8080`
- 改成调新机：`http://192.168.1.B:8080`（替换 B 为新机实际 IP）

**CORS**：新机后端需要允许本机跨域。M1 阶段可以在 runtime 配置：
```yaml
spring:
  web:
    cors:
      allowed-origins: "http://192.168.1.A:3000,http://localhost:3000"
```

### 场景 E：想看新机的数据库数据

**本机用 DBeaver 连新机 MySQL**：
- Host: `192.168.1.B`
- Port: `3306`
- User: `root`
- Password: `root`（开发期，生产要改）

### 场景 F：想看新机服务日志

**方式 1**：远程桌面到新机看
```cmd
cd D:\eaiselp\data\logs\runtime
type runtime.log
```

**方式 2**：本机 SSH 到新机看（需要先开 SSH）
```cmd
ssh user@192.168.1.B
tail -f /d/eaiselp/data/logs/runtime/runtime.log
```

### 场景 G：调试某个 API

**本机 Postman**：
- URL: `http://192.168.1.B:8080/api/runtime/derive`
- Method: POST
- Body:
```json
{
  "role": "team-po",
  "task": "写登录功能 PRD",
  "caseId": "case-test-001"
}
```

## 四、远程操作新机的 3 种方式

### 方式 1：Windows 远程桌面（最简单）

新机一次性配置：
- 设置 → 系统 → 远程桌面 → 启用
- 设置密码（必须）

本机：
- Win+R 输入 `mstsc`
- 输入新机 IP + 用户名密码

**适合**：GUI 操作、看日志、调 Docker Desktop

### 方式 2：SSH（命令行高效）

新机装 OpenSSH Server：
```powershell
# 管理员 PowerShell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
# 防火墙
New-NetFirewallRule -Name sshd -DisplayName 'OpenSSH Server' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22
```

本机 SSH：
```cmd
ssh 用户名@192.168.1.B
```

**适合**：命令行操作、git pull、service.bat

### 方式 3：VS Code Remote-SSH（最舒服）

本机 VSCode 装插件：
- Remote - SSH

`F1` → `Remote-SSH: Connect to Host` → 输入新机 IP → 直接在新机上编辑文件、跑终端。

**适合**：在新机改配置、看代码、跑命令

## 五、推送/拉取的优化策略

### 问题：GitHub push 经常失败（你本机已经遇到过）

**方案 A**：用代理
```cmd
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

**方案 B**：换镜像
```cmd
REM 用 gitee 镜像
git remote add gitee https://gitee.com/你的用户名/eAISEDP.git
git push gitee main
```

**方案 C**：新机直接从本机拉代码（不走 GitHub）
```cmd
REM 在新机上
git clone \\本机IP\D$\AI\mywork\platform
```

### 问题：Maven 依赖每次都下载

**方案**：本机和部署机共用 Maven 本地仓库（局域网共享），或者把 `~/.m2/repository` 打包拷过去。

## 六、性能优化建议

### 新机性能调优

1. **关闭 Windows Defender 实时扫描**（开发目录）：
   ```powershell
   Add-MpPreference -ExclusionPath "D:\eaiselp"
   Add-MpPreference -ExclusionPath "D:\jdk-17"
   Add-MpPreference -ExclusionProcess "java.exe"
   ```

2. **关掉 Windows 视觉效果**：
   - 系统属性 → 高级 → 性能 → 选"最佳性能"

3. **关闭不必要的后台服务**：
   - SysMain / Superfetch（如果有 SSD）
   - Windows Search（如果不在新机搜文件）

4. **设虚拟内存固定大小**：
   - 系统属性 → 高级 → 性能 → 虚拟内存
   - D 盘：自定义 8192-16384 MB

5. **电源计划选"高性能"**：
   - 控制面板 → 电源选项 → 高性能

## 七、数据备份

### 自动备份脚本

**新机**：`D:\eaiselp\deploy\backup.bat`
```cmd
@echo off
set BACKUP_DIR=D:\eaiselp\backups\%date:~0,4%%date:~5,2%%date:~8,2%
mkdir %BACKUP_DIR% 2>nul

echo 备份 MySQL...
docker exec eaiselp-mysql mysqldump -uroot -proot eaiselp > %BACKUP_DIR%\eaiselp.sql

echo 备份 MinIO 数据...
REM 如果 MinIO 数据小，直接复制；大的话用 mc 工具

echo 备份完成: %BACKUP_DIR%
```

加到 Windows 任务计划，每天凌晨 3 点跑：
```powershell
$action = New-ScheduledTaskAction -Execute "D:\eaiselp\deploy\backup.bat"
$trigger = New-ScheduledTaskTrigger -Daily - At 3am
Register-ScheduledTask -Action $action -Trigger $trigger -TaskName "eaiselp-backup"
```

## 八、故障排查

### 症状 1：本机访问新机 API 超时

**排查**：
1. 新机 `ipconfig` 看 IP 对不对
2. 新机 `curl http://localhost:8080` 自身能不能通
3. 新机防火墙 `Get-NetFirewallRule | Where DisplayName -like "*eaiselp*"`
4. 两台机是否同网段（都接同一路由器）
5. 新机有没有连 Wi-Fi（可能 IP 变了）

### 症状 2：新机 docker compose up 拉镜像超时

**排查**：
- 检查镜像加速配置（阶段 6.4）
- 手动 `docker pull mysql:8.0` 看具体错误

### 症状 3：runtime 启动报错

**看日志**：
```cmd
docker logs eaiselp-mysql
docker logs eaiselp-nacos
```

通常是 MySQL/Nacos 没起来，runtime 连不上。

### 症状 4：本机 git push 失败

**绕开**：
```cmd
git push origin main
REM 失败的话等几分钟再试，或者换 gitee
```
